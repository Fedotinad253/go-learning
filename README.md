# Go Backend Developer: роадмап с нуля до первой работы

Этот набор гайдов покрывает весь стек, который спрашивают в вакансиях Junior/Junior+ Go-разработчика.
В каждом файле есть краткая теория, примеры кода, ресурсы и **практические задачи** (это главное).

## Как пользоваться

1. Иди по файлам **по порядку**: каждый следующий опирается на предыдущие.
2. Создай на GitHub один репозиторий `go-learning`, а под каждую задачу отдельную папку (`02-basics/task-03-wordcount`).
3. Отмечай выполненные задачи: `- [ ]` → `- [x]`.
4. **Сначала пиши код сам.** ИИ и готовые решения используй только после своей попытки: для ревью и вопроса «почему так».
   На собеседовании тебя попросят объяснить каждую строку.
5. Задачи помечены сложностью: ⭐ лёгкая, ⭐⭐ средняя, ⭐⭐⭐ сложная. Сложные можно пропустить при первом проходе и вернуться позже.

## Сквозной проект

С файла 06 начинается **Tasks API** — небольшой сервис задач. Каждый следующий гайд что-то в него добавляет:
REST → PostgreSQL → Docker → Redis-кэш → события в Kafka → gRPC-сервис пользователей → метрики и трейсы.
К концу у тебя будет готовый проект для резюме, а в файле 15 описан ещё более серьёзный финальный проект.

## Главные ресурсы

- **go.dev/tour** — официальный интерактивный тур (начни с него)
- **gobyexample.com** — короткие примеры по всем темам
- **go.dev/doc/effective_go** — как писать идиоматичный Go
- Книга *Learning Go* (Jon Bodner) — лучшая книга для старта
- Книга *100 Go Mistakes and How to Avoid Them* (Teiva Harsanyi) — читай после основ, очень полезна для собесов
- Книга *The Go Programming Language* (Donovan, Kernighan) — классика, глубже
- **pkg.go.dev** — документация любых пакетов

## Чек-лист готовности к поиску работы

- [ ] Пишу на Go без подсказок: структуры, интерфейсы, ошибки, горутины, каналы, context
- [ ] Могу объяснить, как устроены slice, map, channel и планировщик горутин
- [ ] Пишу SQL с JOIN, GROUP BY и понимаю индексы и уровни изоляции транзакций
- [ ] Сделал REST API с Postgres, тестами, Docker и CI
- [ ] Работал с Redis, Kafka и gRPC хотя бы в pet-проекте
- [ ] Решил 80–100 задач на LeetCode (easy/medium)
- [ ] Есть финальный проект на GitHub с хорошим README
- [ ] Есть резюме на 1 страницу и прошёл 2–3 пробных собеседования
