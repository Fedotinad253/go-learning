# 19. Алгоритмы, сети, внутренности Go

Эту тему изучай **параллельно со всеми остальными**: 30–60 минут в день. На собеседованиях почти всегда есть live coding и вопросы «как устроено внутри».

## Часть 1. Алгоритмы и структуры данных

### Что знать
- **Сложность (Big-O):** O(1), O(log n), O(n), O(n log n), O(n²). Оценка по времени и памяти.
- **Структуры:** массив и слайс, хеш-таблица, связный список, стек, очередь, дек, куча (heap), дерево и BST, trie, граф.
- **Техники:** два указателя, скользящее окно, бинарный поиск, префиксные суммы, хеш-мапа для подсчёта, сортировки (quick, merge), рекурсия и backtracking, BFS и DFS, жадные алгоритмы, базовое динамическое программирование.

### Как тренироваться
- **LeetCode**: список **NeetCode 150** (neetcode.io) — задачи по темам с видеоразборами. Цель для джуна: 80–100 задач easy/medium.
- Решай **на Go** и вслух проговаривай решение, как на собеседовании.
- Схема: 20 минут думаешь сам → если не получилось, смотри разбор → через 3 дня решаешь заново без подсказок.
- Книга *Грокаем алгоритмы* (Адитья Бхаргава) — простое введение.

## Часть 2. Внутреннее устройство Go

### Что знать
- **Slice:** структура (ptr, len, cap), рост при `append`, общий базовый массив, утечка памяти при подслайсе большого массива.
- **Map:** хеш-таблица (с Go 1.24 реализация на основе Swiss Tables; до этого бакеты по 8 элементов). Почему порядок итерации случайный, почему нельзя взять адрес элемента, почему мапа не потокобезопасна, что происходит при росте.
- **String:** неизменяемый (ptr, len), конвертации `[]byte` ↔ `string` копируют данные.
- **Interface:** пара (тип/itab, данные), стоимость вызова, ловушка с nil.
- **Channel:** структура `hchan` (кольцевой буфер, очереди ждущих отправителей и получателей, мьютекс).
- **Планировщик G-M-P:** локальные и глобальная очереди, work stealing, вытеснение (preemption), что происходит при блокирующем syscall.
- **Память:** стек и куча, **escape analysis** (`go build -gcflags='-m'`), выравнивание полей структур.
- **GC:** конкурентный трёхцветный mark-and-sweep, write barrier, `GOGC`, `GOMEMLIMIT`.
- Рост стека горутин.

### Ресурсы
- go.dev/blog/slices-intro, go.dev/ref/mem (Go memory model)
- Доклады с GopherCon и «Go под капотом» на YouTube (много на русском с конференций GolangConf)
- *100 Go Mistakes and How to Avoid Them*

### Задачи
- [ ] ⭐⭐ **Escape analysis.** Напиши 5 функций (возврат указателя на локальную переменную, замыкание, интерфейс, слайс известного и неизвестного размера). Предскажи, что «убежит» в кучу, и проверь через `-gcflags='-m'`.
- [ ] ⭐⭐ **Выравнивание.** Структура `{a bool; b int64; c bool}`: узнай её размер через `unsafe.Sizeof`. Переставь поля, чтобы уменьшить размер. Объясни почему.
- [ ] ⭐⭐ **Рост слайса.** Программа, которая делает 2000 `append` и печатает cap при каждом изменении. Найди закономерность роста.
- [ ] ⭐⭐⭐ **GC.** Запусти программу с `GODEBUG=gctrace=1`, создающую много мусора. Разберись в выводе. Поиграй с `GOGC=50/200` и `GOMEMLIMIT`.

## Часть 3. Сети и ОС

### Что знать
- Модель TCP/IP, TCP и UDP, тройное рукопожатие, закрытие соединения, TIME_WAIT.
- HTTP/1.1, HTTP/2 (мультиплексирование), HTTP/3 (QUIC), keep-alive.
- TLS-рукопожатие на уровне идеи, сертификаты.
- DNS: как резолвится имя.
- **«Что происходит, когда вводишь google.com в браузере»** — классический вопрос.
- ОС: процесс и поток, переключение контекста, файловые дескрипторы, сигналы (SIGTERM, SIGKILL), epoll/kqueue (как Go netpoller обслуживает тысячи соединений).

### Задачи
- [ ] ⭐⭐ **TCP-эхо-сервер** на пакете `net`: обслуживает много клиентов одновременно (по горутине на соединение), закрывает соединения по таймауту бездействия. Проверь через `nc localhost 9000`.
- [ ] ⭐⭐ **Наблюдение.** Посмотри DNS-запрос (`dig google.com`), TLS (`curl -v https://google.com`), открытые соединения (`lsof -i`).
- [ ] ⭐ **Эссе.** Напиши ответ на «что происходит, когда вводишь URL в браузере» (1–2 страницы) и расскажи его вслух за 5 минут.
