# Словарь терминов

Короткие определения всех основных терминов из гайдов. Термины сгруппированы по файлам, в которых тема разбирается подробно. В скобках — английский оригинал: так термин пишут в документации и вакансиях.

**Как пользоваться**
- Ищи через **Cmd+F**: по-русски или по-английски.
- Определение здесь — это минимум, чтобы понять текст. Подробности и примеры — в гайде, на который ведёт заголовок раздела.
- Хорошая проверка перед собеседованием: закрой определение и объясни термин вслух своими словами за 30 секунд.
- Встретил в гайде или вакансии незнакомое слово, которого здесь нет, — допиши его сам.

## 01. Окружение, терминал, Git
Подробно: [01-setup-macos.md](01-setup-macos.md)

- **Терминал** (terminal) — программа, в которой вводишь текстовые команды. Внутри работает **shell** (на Mac по умолчанию `zsh`), который эти команды выполняет.
- **PATH** — переменная окружения со списком папок, где shell ищет программы. «command not found» часто значит, что папки с программой нет в PATH.
- **Переменная окружения** (environment variable) — пара «имя = значение», которую процесс получает при запуске (`export PORT=8080`). Так сервисам передают конфиг и секреты.
- **Homebrew** — менеджер пакетов для macOS: `brew install go`.
- **Git** — система контроля версий: хранит историю изменений кода.
- **Репозиторий** (repository, repo) — папка проекта вместе со всей историей Git. Локальный — у тебя на диске, удалённый (**remote**, обычно `origin`) — на GitHub.
- **Коммит** (commit) — снимок изменений с сообщением, что и зачем изменено.
- **Ветка** (branch) — отдельная линия разработки. Новую фичу делают в своей ветке, а не в `main`.
- **Merge** — слияние одной ветки в другую. **Rebase** — перенос своих коммитов поверх свежей версии другой ветки, история получается линейной.
- **Конфликт** (merge conflict) — Git не может сам объединить изменения одних и тех же строк, и решать приходится вручную.
- **Pull Request (PR)** — запрос на слияние ветки на GitHub. В нём проходят код-ревью и проверки CI.
- **.gitignore** — файл со списком того, что Git не должен отслеживать: бинарники, `.env`, `vendor/`.
- **Порт** (port) — номер «двери» на машине, через которую программа принимает соединения: HTTP-сервер на 8080, Postgres на 5432.
- **localhost** (127.0.0.1) — адрес своей же машины.
- **Линтер** (linter) — программа, которая ищет ошибки и плохой стиль в коде без запуска. В Go — `golangci-lint`.
- **IDE** — среда разработки: VS Code с расширением Go или GoLand.

## 02. Основы Go
Подробно: [02-go-basics.md](02-go-basics.md)

- **Модуль** (module) — проект Go с файлом `go.mod`, где записаны путь модуля, версия Go и зависимости. **go.sum** — контрольные суммы зависимостей.
- **Пакет** (package) — папка с `.go`-файлами с одинаковым `package`. Единица компиляции и видимости. Программа начинается с `package main` и функции `main`.
- **Экспортируемое имя** (exported) — имя с заглавной буквы, видно из других пакетов. С маленькой — только внутри пакета.
- **Нулевое значение** (zero value) — значение переменной без явной инициализации: `0`, `""`, `false`, `nil`.
- **Короткое объявление** — `x := 5`: объявить и присвоить, тип выводится сам.
- **Затенение** (shadowing) — объявление переменной с тем же именем во внутренней области видимости. Частый источник багов с `err`.
- **iota** — счётчик для объявления последовательных констант (перечислений).
- **Вариадическая функция** (variadic) — принимает любое число аргументов: `func sum(nums ...int)`.
- **Замыкание** (closure) — функция, которая захватывает переменные из окружающей области видимости.
- **defer** — откладывает вызов до выхода из функции. Отложенные вызовы выполняются в обратном порядке. Используют для `Close()`, `Unlock()`.
- **panic** — аварийная остановка: раскручивает стек, выполняя `defer`. Для невосстановимых ошибок, а не для обычной обработки.
- **recover** — внутри `defer` перехватывает panic и не даёт программе упасть.
- **Указатель** (pointer) — адрес значения в памяти: `*T` — тип, `&x` — взять адрес, `*p` — получить значение.
- **Передача по значению** — в Go всё передаётся копией. Слайс, мапа, канал копируются как маленькие заголовки, которые указывают на общие данные.
- **Массив** (array) — последовательность фиксированной длины, длина входит в тип: `[3]int` и `[4]int` — разные типы.
- **Слайс** (slice) — «окно» в массив: указатель на массив, длина (**len**) и ёмкость (**cap**). Несколько слайсов могут смотреть в один массив.
- **append** — добавляет элементы в слайс. Если не хватает cap, выделяет новый массив побольше и копирует данные, после этого старый и новый слайсы уже не связаны.
- **Мапа** (map) — хеш-таблица «ключ → значение». Порядок обхода случайный. Писать в nil-мапу нельзя (panic). Одновременная запись из нескольких горутин без синхронизации — фатальная ошибка.
- **Строка** (string) — неизменяемая последовательность **байт**, обычно в кодировке UTF-8. `len(s)` — число байт, а не символов.
- **Байт** (byte) — `uint8`, 8 бит.
- **Руна** (rune) — `int32`, один символ Unicode (code point). `for range` по строке идёт по рунам.
- **UTF-8** — кодировка, в которой символ занимает от 1 до 4 байт: латиница — 1 байт, кириллица — 2.
- **Структура** (struct) — набор именованных полей.
- **Метод** (method) — функция с **ресивером** (receiver): `func (a *Account) Deposit(...)`.
- **Ресивер по значению и по указателю** — по значению метод работает с копией. По указателю может менять исходный объект и не копирует большие структуры.
- **Встраивание** (embedding) — поле без имени в структуре: методы встроенного типа становятся доступны снаружи. Композиция вместо наследования.
- **Теги структуры** (struct tags) — метаданные полей: `json:"name"`, `db:"id"`.
- **go fmt / gofmt** — стандартный форматтер кода. **go vet** — встроенная проверка на подозрительный код.
- **init()** — функция, которая выполняется автоматически при загрузке пакета, до `main`. Порядок: импортированные пакеты, затем глобальные переменные пакета, затем его `init`.
- **internal/** — папка, пакеты из которой можно импортировать только внутри своего модуля.
- **Константа без типа** (untyped constant) — константа, которая хранится с произвольной точностью и получает тип только при использовании. Поэтому `1 / 3` для констант — это целочисленное деление, равное 0.
- **Переполнение** (overflow) — значение вышло за пределы типа. Во время выполнения происходит молча (`int8(127)+1 == -128`), для констант это ошибка компиляции.
- **Метка** (label) — имя перед циклом: `break outer` выходит сразу из внешнего цикла.
- **Переменная цикла в Go 1.22** — с Go 1.22 каждая итерация `for` получает свою копию переменной. Раньше переменная была одна, и замыкания или `&v` видели последнее значение. Поведение задаёт версия в `go.mod`.
- **Именованный результат** (named result) — `func f() (n int, err error)`. Отложенная функция может изменить его перед возвратом.
- **Функция как значение** (first-class function) — функцию можно положить в переменную, мапу или поле структуры, передать и вернуть.
- **Множество** (set) — в Go делается через `map[T]struct{}`: пустая структура занимает 0 байт.
- **Анонимная структура** — структура без объявленного типа: `struct{ OK bool }{OK: true}`.
- **Итератор** (iterator, `iter.Seq`) — функция вида `func(yield func(T) bool)`, по которой можно идти через `for … range` (Go 1.23). Если `yield` вернул `false`, итератор обязан остановиться.
- **min, max, clear** — встроенные функции Go 1.21: минимум и максимум из аргументов, очистка мапы (удаляет все ключи) или слайса (обнуляет элементы).
- **Эталонная дата** — `2006-01-02 15:04:05`: формат времени в Go задаётся этой датой, а не буквами вроде `YYYY-MM-DD`.

## 03. Интерфейсы, ошибки, дженерики
Подробно: [03-interfaces-errors-generics.md](03-interfaces-errors-generics.md)

- **Интерфейс** (interface) — набор методов. Любой тип с этими методами реализует интерфейс **неявно**, без слова `implements`.
- **«Принимай интерфейсы, возвращай структуры»** — принцип Go: интерфейс объявляют там, где он используется, и делают маленьким (1–3 метода).
- **any** (`interface{}`) — пустой интерфейс, ему соответствует любое значение.
- **Приведение типа** (type assertion) — `v, ok := x.(T)`: достать конкретный тип из интерфейса.
- **Type switch** — `switch v := x.(type)`: ветвление по конкретному типу значения.
- **nil-интерфейс** — интерфейс равен `nil`, только если внутри нет ни типа, ни значения. Интерфейс с типом `*MyErr` и значением `nil` — уже **не** nil. Классическая ловушка с возвратом ошибок.
- **io.Reader / io.Writer** — базовые интерфейсы чтения и записи потока байт. На них построена вся работа с файлами, сетью, HTTP.
- **error** — встроенный интерфейс с методом `Error() string`. Ошибки в Go — обычные значения, их возвращают последним результатом.
- **Sentinel-ошибка** — заранее объявленная ошибка-значение для сравнения: `var ErrNotFound = errors.New("not found")`.
- **Оборачивание ошибки** (wrapping) — `fmt.Errorf("get user %d: %w", id, err)`: добавить контекст и сохранить исходную ошибку внутри.
- **errors.Is** — есть ли в цепочке обёрнутых ошибок конкретное значение. **errors.As** — есть ли ошибка конкретного типа, и достать её.
- **Свой тип ошибки** (custom error) — структура с методом `Error()`, может нести поля (код, поле валидации).
- **Дженерики** (generics) — функции и типы с параметрами типа: `func Map[T, U any](s []T, f func(T) U) []U`.
- **Параметр типа** (type parameter) — `T` в квадратных скобках.
- **Ограничение** (constraint) — интерфейс, описывающий, какие типы можно подставить: `any`, `comparable`, `cmp.Ordered`, своё `~int | ~float64`.
- **comparable** — типы, которые можно сравнивать через `==` (подходят как ключ мапы).
- **~T** — «любой тип, у которого базовый тип T»: `~int` подходит и для `type UserID int`.

## 04. Конкурентность
Подробно: [04-concurrency.md](04-concurrency.md)

- **Конкурентность и параллелизм** (concurrency vs parallelism) — конкурентность: задачи выполняются вперемешку и независимо. Параллелизм: буквально одновременно на нескольких ядрах. Конкурентный код может работать и на одном ядре.
- **Горутина** (goroutine) — лёгкий поток, которым управляет рантайм Go: стартует со стеком в несколько КБ, их можно запускать сотнями тысяч. Запуск — `go f()`.
- **Планировщик G-M-P** — модель планировщика Go: G — горутина, M — поток ОС, P — логический процессор с очередью горутин. M выполняет G, только держа P.
- **GOMAXPROCS** — число P, то есть сколько горутин могут выполняться параллельно. По умолчанию — число доступных ядер.
- **Канал** (channel) — типизированная труба для передачи значений между горутинами. «Не общайтесь через общую память, делитесь памятью через общение».
- **Небуферизованный канал** — отправка блокируется, пока кто-то не примет значение. **Буферизованный** — блокируется, только когда буфер полон.
- **Закрытие канала** — `close(ch)`: сигнал «больше значений не будет». Читать из закрытого можно (придут нулевые значения, `ok == false`), писать — panic. Закрывает отправитель.
- **nil-канал** — блокирует навсегда и отправку, и чтение. В `select` используют, чтобы «выключить» ветку.
- **select** — ждёт сразу несколько операций с каналами и выполняет ту, что готова первой. `default` делает его неблокирующим.
- **Мьютекс** (sync.Mutex) — блокировка: в критической секции в один момент только одна горутина. **RWMutex** — много читателей или один писатель.
- **WaitGroup** — ждёт завершения группы горутин: `Add`, `Done`, `Wait`.
- **sync.Once** — выполнить код ровно один раз (ленивая инициализация).
- **Атомарные операции** (sync/atomic) — неделимые операции над числами без мьютекса: счётчики, флаги.
- **errgroup** — `golang.org/x/sync/errgroup`: запускает группу горутин, ждёт их и возвращает первую ошибку, отменяя остальные через context.
- **context** — передаёт по цепочке вызовов сигнал отмены, дедлайн и значения запроса. Первым аргументом функции: `ctx context.Context`.
- **WithCancel / WithTimeout / WithDeadline** — создают дочерний context, который отменится вручную, через время или в момент. `cancel()` нужно вызывать всегда (`defer cancel()`).
- **Гонка данных** (data race) — две горутины одновременно обращаются к одной памяти, и хотя бы одна пишет, без синхронизации. Поведение непредсказуемо.
- **Race detector** — `go test -race` / `go run -race`: находит гонки во время выполнения.
- **Deadlock** (взаимная блокировка) — горутины ждут друг друга бесконечно. Если заблокированы все, Go падает с `all goroutines are asleep`.
- **Утечка горутин** (goroutine leak) — горутина навсегда заблокирована (ждёт канал, который никто не закроет) и не освобождает память.
- **Worker pool** — фиксированное число горутин-воркеров забирает задачи из общего канала. Ограничивает параллелизм.
- **Fan-out / fan-in** — раздать работу нескольким горутинам / собрать результаты из нескольких каналов в один.
- **Pipeline** — цепочка этапов, соединённых каналами: каждый этап читает из предыдущего и пишет в следующий.
- **Семафор** (semaphore) — ограничитель «не больше N одновременно». В Go — буферизованный канал на N или `x/sync/semaphore`.
- **Rate limiting** — ограничение частоты операций (не больше N в секунду). Популярный алгоритм — **token bucket**: `golang.org/x/time/rate`.
- **Backpressure** — механизм, когда медленный потребитель притормаживает быстрого производителя (например, заполненный буферизованный канал блокирует отправку).
- **Graceful shutdown** — корректная остановка: перестать принимать новую работу, доделать текущую, закрыть ресурсы, выйти.

## 05. Тестирование
Подробно: [05-testing.md](05-testing.md)

- **Unit-тест** — проверяет одну функцию или тип в изоляции от БД и сети.
- **Интеграционный тест** (integration) — проверяет работу с настоящими зависимостями: БД, Redis, Kafka.
- **E2E-тест** (end-to-end) — проверяет систему целиком через её внешний API, как пользователь.
- **Табличный тест** (table-driven test) — слайс кейсов «вход → ожидаемый результат» и цикл по нему. Стандарт в Go.
- **Подтест** — `t.Run(name, func(t *testing.T){...})`: у каждого кейса своё имя, можно запустить отдельно.
- **t.Parallel()** — тест выполняется параллельно с другими такими же.
- **testify** — библиотека проверок: `assert` (продолжает тест после ошибки) и `require` (останавливает тест).
- **Мок** (mock) — подделка зависимости, которая проверяет, как её вызвали. **Стаб** (stub) — подделка, которая просто возвращает заготовленные ответы. **Фейк** (fake) — упрощённая рабочая реализация (in-memory репозиторий).
- **mockery / gomock** — генераторы моков по интерфейсам.
- **httptest** — стандартный пакет для тестов HTTP: `httptest.NewRecorder` (записать ответ хендлера) и `httptest.NewServer` (поднять тестовый сервер).
- **testcontainers** — запуск настоящих зависимостей (Postgres, Redis) в Docker прямо из теста.
- **Бенчмарк** (benchmark) — `func BenchmarkX(b *testing.B)`: замер скорости и аллокаций, запуск `go test -bench . -benchmem`.
- **Фаззинг** (fuzzing) — `func FuzzX(f *testing.F)`: Go сам генерирует случайные входные данные и ищет падения.
- **Покрытие** (coverage) — какая доля кода выполнилась в тестах: `go test -cover`, отчёт `-coverprofile`.
- **TDD** (test-driven development) — сначала падающий тест, потом код, который его проходит, потом рефакторинг.
- **Флаки-тест** (flaky test) — тест, который то проходит, то падает без изменений в коде. Обычно из-за времени, порядка или гонок.

## 06. HTTP и REST
Подробно: [06-http-rest.md](06-http-rest.md)

- **HTTP** — текстовый протокол «запрос — ответ» поверх TCP. Запрос: метод, путь, заголовки, тело. Ответ: статус-код, заголовки, тело.
- **Методы** — `GET` (получить), `POST` (создать), `PUT` (заменить целиком), `PATCH` (изменить часть), `DELETE` (удалить).
- **Безопасный метод** (safe) — не меняет данные на сервере: GET, HEAD.
- **Идемпотентный метод** (idempotent) — повтор запроса даёт тот же итоговый результат: GET, PUT, DELETE. POST не идемпотентен.
- **Статус-коды** — 2xx успех (200 OK, 201 Created, 204 No Content), 3xx редирект, 4xx ошибка клиента (400, 401, 403, 404, 409 Conflict, 422, 429 Too Many Requests), 5xx ошибка сервера (500, 502, 503, 504).
- **401 и 403** — 401: «не знаю, кто ты» (нет или неверный токен). 403: «знаю, но нельзя».
- **Заголовки** (headers) — метаданные запроса и ответа: `Content-Type`, `Authorization`, `Cache-Control`.
- **Query-параметры** — после `?` в URL: `/tasks?done=true&limit=10`. **Path-параметры** — часть пути: `/tasks/{id}`.
- **REST** — стиль API: ресурсы адресуются URL (`/tasks/42`), действия — HTTP-методами, сервер не хранит состояние клиента между запросами.
- **JSON** — текстовый формат данных. **Маршалинг / анмаршалинг** (marshal/unmarshal) — превращение структуры в JSON и обратно.
- **Хендлер** (handler) — функция, обрабатывающая запрос: интерфейс `http.Handler` с методом `ServeHTTP`.
- **Роутер / мультиплексор** (router, mux) — сопоставляет метод и путь с хендлером: стандартный `http.ServeMux`, chi, gin, echo, fiber.
- **Middleware** — обёртка над хендлером (`func(http.Handler) http.Handler`), которая делает общую работу для всех запросов: логирование, аутентификация, recover, request-id, CORS.
- **Request ID** — уникальный id запроса в заголовке и логах, чтобы найти все записи про один запрос.
- **CORS** — механизм браузера: страница с одного домена может обращаться к API на другом, только если сервер разрешил это заголовками `Access-Control-Allow-*`.
- **Аутентификация и авторизация** (authentication vs authorization) — аутентификация: кто ты (логин). Авторизация: что тебе можно (права).
- **Хеширование пароля** — пароль хранят не в открытом виде, а как медленный хеш с солью (**bcrypt**, argon2). **Соль** (salt) — случайная добавка, чтобы одинаковые пароли давали разные хеши.
- **JWT** (JSON Web Token) — подписанный токен из трёх частей `header.payload.signature`. Сервер проверяет подпись и не ходит в БД. Данные внутри не зашифрованы, только подписаны.
- **Access и refresh token** — короткоживущий токен для запросов и долгоживущий для получения нового access token.
- **Cookie** — данные, которые браузер хранит и отправляет с каждым запросом на домен. Флаги `HttpOnly`, `Secure`, `SameSite` защищают от кражи.
- **HTTPS / TLS** — HTTP поверх шифрованного соединения TLS.
- **Валидация** (validation) — проверка входных данных (обязательные поля, длины, форматы) до бизнес-логики.
- **Пагинация** (pagination) — выдача по частям. **Offset** (`limit/offset`) — просто, но медленно на больших смещениях. **Курсорная** (cursor, keyset) — «дай после id X», быстро и стабильно.
- **OpenAPI / Swagger** — формат описания REST API в YAML/JSON. Из него генерируют документацию, клиентов и серверный код.
- **Таймауты сервера** — `ReadTimeout`, `WriteTimeout`, `IdleTimeout` в `http.Server`. Без них медленный клиент может держать соединения бесконечно.
- **Keep-alive** — повторное использование одного TCP-соединения для нескольких HTTP-запросов.
- **Ретрай** (retry) — повтор неудавшегося запроса, обычно с увеличивающейся паузой. Безопасен только для идемпотентных операций.

## 07. SQL и PostgreSQL
Подробно: [07-sql-postgres.md](07-sql-postgres.md)

- **Реляционная БД** — данные в таблицах (строки и колонки), связи между таблицами через ключи, запросы на SQL.
- **Первичный ключ** (primary key) — уникальный идентификатор строки.
- **Внешний ключ** (foreign key) — колонка, ссылающаяся на первичный ключ другой таблицы. БД не даст сослаться на несуществующую строку.
- **Ограничения** (constraints) — `NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY`: правила, которые БД проверяет сама.
- **Нормализация** — разбиение данных на таблицы без дублирования. **Денормализация** — осознанное дублирование ради скорости чтения.
- **JOIN** — соединение таблиц. `INNER` — только совпадения. `LEFT` — все строки слева, справа `NULL`, если пары нет. `RIGHT`, `FULL` — аналогично. `CROSS` — все комбинации.
- **GROUP BY / HAVING** — группировка с агрегатами (`COUNT`, `SUM`, `AVG`). `WHERE` фильтрует строки до группировки, `HAVING` — группы после.
- **Подзапрос** (subquery) — запрос внутри запроса.
- **CTE** — `WITH x AS (...)`: именованный подзапрос для читаемости. Бывает рекурсивным.
- **Оконная функция** (window function) — агрегат по «окну» строк без схлопывания: `ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at)`.
- **UPSERT** — вставить или обновить при конфликте: `INSERT ... ON CONFLICT (key) DO UPDATE / DO NOTHING`.
- **Индекс** (index) — отдельная структура для быстрого поиска, обычно **B-tree**. Ускоряет чтение, замедляет запись и занимает место.
- **Составной индекс** (composite) — по нескольким колонкам. Работает слева направо: индекс `(a, b)` помогает для `WHERE a=…` и `WHERE a=… AND b=…`, но не для `WHERE b=…`.
- **Покрывающий индекс** (covering) — содержит все нужные запросу колонки, и таблицу читать не нужно (index-only scan).
- **EXPLAIN / EXPLAIN ANALYZE** — показать план выполнения запроса / выполнить и показать реальное время. **Seq Scan** — полный проход по таблице, **Index Scan** — по индексу.
- **Транзакция** (transaction) — группа операций, которая выполняется целиком или не выполняется вообще: `BEGIN … COMMIT / ROLLBACK`.
- **ACID** — свойства транзакций. Atomicity (всё или ничего), Consistency (данные остаются корректными), Isolation (транзакции не мешают друг другу), Durability (после COMMIT данные не теряются).
- **Уровни изоляции** — Read Uncommitted, **Read Committed** (по умолчанию в Postgres), Repeatable Read, Serializable. Чем выше уровень, тем меньше аномалий и больше конфликтов.
- **Аномалии** — **грязное чтение** (видно незакоммиченные данные чужой транзакции), **неповторяющееся чтение** (повторное чтение строки даёт другое значение), **фантомное чтение** (повторный запрос возвращает новые строки), **потерянное обновление** (lost update — две транзакции перезаписали друг друга), **write skew**.
- **MVCC** — способ Postgres обеспечивать изоляцию: при изменении создаётся новая версия строки, и читатели не блокируют писателей.
- **VACUUM** — процесс Postgres, который убирает старые версии строк, оставшиеся после MVCC.
- **Блокировки** (locks) — `SELECT ... FOR UPDATE` блокирует выбранные строки до конца транзакции. **SKIP LOCKED** — пропустить уже заблокированные строки (очереди задач, outbox).
- **Оптимистичная блокировка** — колонка `version`: обновление проходит, только если версия не изменилась (`WHERE id=… AND version=…`).
- **Deadlock в БД** — две транзакции ждут блокировки друг друга. Postgres убивает одну из них с ошибкой.
- **Миграция** (migration) — версионированный SQL-файл, изменяющий схему (`up` и `down`). Инструменты: goose, golang-migrate.
- **Пул соединений** (connection pool) — набор заранее открытых соединений с БД, которые переиспользуются. `pgxpool`, настройки `MaxConns`.
- **database/sql** — стандартный интерфейс к SQL-базам. **pgx** — быстрый драйвер и набор инструментов для Postgres.
- **sqlc** — генерирует типизированный Go-код из SQL-запросов.
- **ORM** — библиотека, которая отображает таблицы в объекты и сама строит SQL (GORM). Удобно, но SQL скрыт.
- **SQL-инъекция** (SQL injection) — подстановка пользовательского ввода прямо в текст SQL. Защита — только параметры (`$1`, `$2`), никогда `fmt.Sprintf`.
- **Проблема N+1** — один запрос за списком и ещё N запросов за связанными данными каждого элемента. Решение — JOIN или `WHERE id = ANY($1)`.

## 08. Docker, CI/CD, Kubernetes
Подробно: [08-docker-ci-k8s.md](08-docker-ci-k8s.md)

- **Контейнер** (container) — изолированный процесс со своей файловой системой, сетью и лимитами ресурсов. Делит ядро с хостом, поэтому легче виртуалки.
- **Образ** (image) — шаблон контейнера только для чтения: файловая система и команда запуска. Состоит из **слоёв** (layers), которые кэшируются.
- **Dockerfile** — инструкция сборки образа: `FROM`, `COPY`, `RUN`, `CMD`.
- **Многоэтапная сборка** (multi-stage build) — собрать бинарник в большом образе с Go, скопировать его в маленький (`scratch`, `distroless`, `alpine`). Итоговый образ весит мегабайты.
- **Реестр** (registry) — хранилище образов: Docker Hub, GitHub Container Registry. **Тег** (tag) — версия образа: `tasks-api:1.2.0`.
- **Volume** — хранилище данных вне контейнера: данные переживают пересоздание контейнера.
- **Docker network** — виртуальная сеть, в которой контейнеры обращаются друг к другу по имени сервиса.
- **Docker Compose** — описание нескольких контейнеров в `docker-compose.yml` и запуск одной командой `docker compose up`.
- **.dockerignore** — что не отправлять в контекст сборки (`.git`, бинарники, `.env`).
- **CI** (continuous integration) — автоматическая сборка, линтер и тесты на каждый push или PR.
- **CD** (continuous delivery / deployment) — автоматическая доставка собранной версии на окружение.
- **GitHub Actions** — CI в GitHub: **workflow** (файл в `.github/workflows`) → **job** → **step**.
- **Makefile** — короткие команды для частых действий: `make test`, `make run`, `make lint`.
- **Kubernetes (k8s)** — оркестратор: запускает контейнеры на кластере машин, перезапускает упавшие, масштабирует, раздаёт трафик.
- **Кластер** (cluster) и **нода** (node) — набор машин под управлением Kubernetes / одна такая машина.
- **Pod** — минимальная единица в k8s: один или несколько контейнеров с общей сетью. Поды смертны и пересоздаются.
- **Deployment** — описывает, сколько реплик пода нужно и из какого образа. Делает **rolling update** — постепенную замену старых подов новыми.
- **ReplicaSet** — поддерживает заданное число одинаковых подов (им управляет Deployment).
- **Service** — постоянный адрес и балансировка для набора подов.
- **Ingress** — правила входа HTTP-трафика снаружи кластера на сервисы (по домену и пути).
- **ConfigMap / Secret** — конфигурация и секреты, которые передаются в поды как переменные окружения или файлы.
- **Probes** — проверки здоровья. **Liveness**: жив ли процесс (если нет — перезапуск). **Readiness**: готов ли принимать трафик (если нет — убрать из балансировки). **Startup**: закончился ли запуск.
- **Requests / limits** — сколько CPU и памяти поду гарантировано / максимум, который он может взять.
- **Namespace** — логическое разделение ресурсов в кластере (по командам, окружениям).
- **kubectl** — CLI для Kubernetes. **Helm** — менеджер пакетов (чартов) для k8s.

## 09. Linux
Подробно: [09-linux.md](09-linux.md)

- **Процесс** (process) — запущенная программа со своей памятью. **PID** — его номер, **PPID** — номер родителя.
- **Поток** (thread) — единица выполнения внутри процесса, потоки делят память процесса.
- **Сигнал** (signal) — асинхронное уведомление процессу. **SIGTERM** — вежливая просьба завершиться. **SIGKILL** — убить немедленно, перехватить нельзя. **SIGINT** — Ctrl+C. **SIGHUP** — часто «перечитай конфиг». **SIGQUIT** — Go печатает стеки всех горутин.
- **Код выхода** (exit code) — число, с которым завершился процесс: 0 — успех. **137** = 128 + 9 — процесс убит через SIGKILL (часто OOM).
- **PID 1** — первый процесс в системе или контейнере. Должен пересылать сигналы и собирать завершённые дочерние процессы. Отсюда правило exec-формы `CMD ["./app"]` в Dockerfile.
- **Зомби** (zombie) — завершившийся процесс, код выхода которого не прочитал родитель. **Сирота** (orphan) — процесс, чей родитель умер.
- **Файловый дескриптор** (file descriptor, fd) — номер открытого файла, сокета или пайпа в процессе. Лимит — `ulimit -n`. Отсюда ошибка `too many open files`.
- **stdin / stdout / stderr** — стандартные потоки ввода, вывода и ошибок (fd 0, 1, 2).
- **Пайп** (pipe) — `a | b`: вывод одной команды на вход другой. **Перенаправление** — `>` в файл, `>>` дописать, `2>&1` ошибки туда же.
- **Права доступа** (permissions) — `rwx` для владельца, группы и остальных. `chmod`, `chown`. **root** — суперпользователь.
- **/proc** — виртуальная файловая система с информацией о процессах и ядре.
- **systemd** — менеджер служб в большинстве дистрибутивов. **Unit** — описание службы. **journald** / `journalctl` — системные логи.
- **cgroups** — механизм ядра для ограничения CPU и памяти группы процессов. На нём построены лимиты Docker и Kubernetes.
- **OOM killer** — механизм ядра, который убивает процесс при нехватке памяти или превышении лимита cgroup.
- **GOMEMLIMIT** — мягкий лимит памяти для Go-рантайма: при приближении к нему GC работает чаще.
- **Состояния TCP** — **LISTEN** (ждёт соединений), **ESTABLISHED** (активное), **TIME_WAIT** (закрыто нами, ждём на случай опоздавших пакетов), **CLOSE_WAIT** (другая сторона закрыла, а наше приложение ещё нет — часто признак незакрытых соединений).
- **0.0.0.0 и 127.0.0.1** — слушать на всех интерфейсах / только на локальном. Сервис в контейнере на 127.0.0.1 снаружи недоступен.
- **strace** — показывает системные вызовы процесса.
- **cron** — планировщик задач по расписанию.

## 10. Redis
Подробно: [10-redis.md](10-redis.md)

- **In-memory хранилище** — данные в оперативной памяти: очень быстро, объём ограничен памятью.
- **Ключ–значение** (key-value) — модель данных: значение доступно по строковому ключу.
- **TTL** (time to live) — время жизни ключа, после которого он удаляется: `EXPIRE`, `SET k v EX 60`.
- **Типы данных Redis** — String, Hash (объект с полями), List (очередь), Set (уникальные значения), **Sorted Set** (значения со счётом, отсортированы — рейтинги), Stream (лог с группами потребителей).
- **Атомарность команд** — Redis выполняет команды в одном потоке, поэтому каждая команда атомарна.
- **MULTI / EXEC** — транзакция: группа команд выполняется подряд без вклинивания чужих.
- **Пайплайн** (pipelining) — отправить много команд за один сетевой круг, не дожидаясь ответа на каждую.
- **Lua-скрипт** — атомарное выполнение нескольких операций с логикой на сервере.
- **RDB и AOF** — снапшоты памяти на диск / журнал всех операций записи. Способы не потерять данные при перезапуске.
- **Политика вытеснения** (eviction policy) — что удалять при нехватке памяти: `allkeys-lru` — давно не использованные ключи.
- **Кэш** (cache) — быстрое хранилище копий данных. **Cache hit** — данные нашлись в кэше, **cache miss** — нет, идём в БД.
- **Cache-aside** — приложение сначала смотрит в кэш, при промахе читает из БД и кладёт в кэш. Самый частый паттерн.
- **Write-through / write-behind** — запись сразу в кэш и БД / сначала в кэш, а в БД позже асинхронно.
- **Инвалидация кэша** (cache invalidation) — удаление или обновление устаревших данных в кэше при изменении источника.
- **Cache stampede** (thundering herd) — ключ истёк, и тысячи запросов одновременно идут в БД.
- **singleflight** — `x/sync/singleflight`: одинаковые одновременные запросы выполняются один раз, остальные ждут общий результат.
- **Распределённая блокировка** (distributed lock) — блокировка между несколькими экземплярами сервиса: `SET lock <uuid> NX PX 10000`.
- **Pub/Sub** — публикация сообщений подписчикам без хранения: кто не слушал, тот не получил.
- **SCAN и KEYS** — `KEYS *` блокирует Redis на всё время обхода. `SCAN` обходит ключи порциями.

## 11. Kafka и брокеры сообщений
Подробно: [11-kafka.md](11-kafka.md)

- **Брокер сообщений** (message broker) — посредник, через которого сервисы обмениваются сообщениями асинхронно: Kafka, RabbitMQ.
- **Синхронное и асинхронное взаимодействие** — синхронное: вызвал и ждёшь ответа (HTTP, gRPC). Асинхронное: отправил событие и пошёл дальше.
- **Событие** (event) — факт, который уже произошёл: `task.created`. **Команда** (command) — просьба что-то сделать.
- **Producer / consumer** — тот, кто отправляет сообщения / тот, кто их читает.
- **Topic** — именованный поток сообщений, лог только на добавление.
- **Partition** — часть топика. Порядок сообщений гарантирован только внутри партиции. Партиции дают параллелизм.
- **Ключ сообщения** (key) — сообщения с одинаковым ключом попадают в одну партицию и обрабатываются по порядку.
- **Offset** — номер сообщения в партиции. **Коммит offset** — consumer сообщает, до какого места обработал.
- **Consumer group** — группа потребителей, делящих партиции топика: каждая партиция читается одним consumer'ом группы.
- **Rebalance** — перераспределение партиций при добавлении или падении consumer'а.
- **Consumer lag** — насколько consumer отстаёт от последних сообщений. Главная метрика здоровья потребителя.
- **Retention** — сколько времени Kafka хранит сообщения, независимо от того, прочитаны ли они.
- **Репликация, ISR, acks** — копии партиции на нескольких брокерах / синхронные реплики / сколько реплик должны подтвердить запись (`acks=all` — надёжнее всего).
- **Семантики доставки** — **at-most-once** (может потеряться), **at-least-once** (может прийти дважды, самая частая), **exactly-once** (ровно один раз, сложно и дорого).
- **Идемпотентный обработчик** (idempotent consumer) — повторная обработка того же сообщения не меняет результат. Обычно хранят id обработанных событий.
- **Transactional outbox** — событие пишется в таблицу `outbox` в той же транзакции, что и данные, а отдельный процесс отправляет его в брокер. Решает проблему «записали в БД, но не отправили в Kafka».
- **DLQ** (dead letter queue) — отдельная очередь или топик для сообщений, которые не удалось обработать после всех попыток.
- **Экспоненциальная задержка** (exponential backoff) — пауза между повторами растёт: 1с, 2с, 4с, 8с.

## 12. RabbitMQ
Подробно: [12-rabbitmq.md](12-rabbitmq.md)

- **AMQP** — протокол, по которому работает RabbitMQ.
- **Exchange** — точка, куда producer публикует сообщение. Exchange решает, в какие очереди его положить.
- **Типы exchange** — **direct** (точное совпадение ключа), **topic** (шаблоны с `*` и `#`), **fanout** (во все привязанные очереди), headers (по заголовкам).
- **Binding** — правило связи exchange и очереди.
- **Routing key** — ключ сообщения, по которому exchange маршрутизирует.
- **Queue** — очередь, где сообщения ждут потребителя. После подтверждения сообщение удаляется.
- **Ack / Nack / Reject** — подтвердить обработку / отказаться, вернув в очередь или отправив в DLX.
- **autoAck** — сообщение считается обработанным сразу при выдаче потребителю. При падении потребителя теряется.
- **Prefetch (QoS)** — сколько неподтверждённых сообщений брокер может выдать одному потребителю одновременно.
- **Durable / persistent** — очередь переживает перезапуск брокера / сообщение записывается на диск.
- **Publisher confirms** — брокер подтверждает producer'у, что принял сообщение.
- **Quorum queue** — реплицируемая очередь на алгоритме Raft. Рекомендуемый тип для надёжных очередей.
- **Stream** — тип очереди в RabbitMQ, похожий на лог Kafka: сообщения не удаляются после чтения.
- **DLX** (dead letter exchange) — exchange, куда уходят отклонённые, просроченные или вытесненные сообщения.

## 13. NoSQL: MongoDB и ClickHouse
Подробно: [13-nosql-mongodb-clickhouse.md](13-nosql-mongodb-clickhouse.md)

- **NoSQL** — общее название нереляционных БД: документные, ключ–значение, колоночные, графовые.
- **Документ** (document) — JSON-подобный объект, единица хранения в MongoDB. **Коллекция** (collection) — набор документов.
- **BSON** — бинарный формат JSON в MongoDB, поддерживает дополнительные типы (даты, ObjectID).
- **ObjectID** — 12-байтный идентификатор документа по умолчанию, содержит время создания.
- **Гибкая схема** (schemaless) — документы одной коллекции могут иметь разные поля.
- **Встраивание и ссылки** (embedding vs referencing) — хранить связанные данные внутри документа / в отдельной коллекции с id.
- **Aggregation pipeline** — цепочка стадий обработки в MongoDB: `$match`, `$group`, `$sort`, `$project`, `$lookup`.
- **Replica set** — группа копий MongoDB: один primary принимает запись, secondary — копии.
- **Шардирование** (sharding) и **shard key** — разбиение данных между серверами / поле, по которому решается, на какой сервер попадёт документ.
- **Write concern / read concern** — сколько узлов должны подтвердить запись / какие данные видит чтение.
- **TTL-индекс** — индекс, по которому MongoDB сам удаляет документы через заданное время.
- **OLTP и OLAP** — много мелких транзакций (интернет-магазин) / тяжёлые аналитические запросы по большим объёмам (отчёты).
- **Колоночная БД** (columnar) — хранит данные по колонкам, а не по строкам: быстро агрегирует и хорошо сжимает, плохо обновляет отдельные строки. ClickHouse.
- **MergeTree** — основной движок таблиц ClickHouse: данные пишутся кусками (parts), которые в фоне сливаются. **ReplacingMergeTree** — убирает дубли по ключу при слиянии.
- **Ключ сортировки** (ORDER BY в ClickHouse) — порядок хранения данных и основа разреженного первичного индекса.
- **Партиционирование** (PARTITION BY) — разбиение таблицы на части, обычно по времени.
- **Materialized view** — в ClickHouse: запрос, который считает данные при каждой вставке и пишет результат в другую таблицу.
- **Батчевая вставка** (batch insert) — вставка тысяч строк одним запросом вместо отдельных запросов.
- **Полнотекстовый поиск** (full-text search) — поиск по словам с морфологией и релевантностью. Elasticsearch, OpenSearch.

## 14. Объектное хранилище S3
Подробно: [14-s3-object-storage.md](14-s3-object-storage.md)

- **Объектное хранилище** (object storage) — хранилище файлов-объектов с доступом по HTTP API. Стандарт де-факто — API Amazon S3.
- **S3-совместимое** (S3-compatible) — хранилище с тем же API: Yandex Object Storage, Selectel, Cloudflare R2, RustFS, Garage.
- **Bucket** — контейнер для объектов.
- **Object** и **ключ** (key) — файл с метаданными / его полное имя внутри бакета: `attachments/2026/11/a1b2.pdf`.
- **Префикс** (prefix) — начало ключа. Папок в S3 нет, консоль показывает префиксы как папки.
- **Метаданные объекта** — `Content-Type`, размер, свои заголовки `x-amz-meta-*`.
- **ETag** — хеш содержимого объекта.
- **Multipart upload** — загрузка большого файла частями, которые можно отправлять параллельно и повторять при ошибке.
- **Presigned URL** — временная подписанная ссылка на загрузку или скачивание конкретного объекта напрямую, без ключей доступа и мимо сервиса.
- **Versioning** — хранение предыдущих версий объектов.
- **Lifecycle rules** — правила автоматического удаления или переноса объектов в холодное хранилище.
- **Bucket policy / IAM** — правила доступа к бакету / система пользователей и ролей в облаке.
- **Path-style и virtual-hosted style** — адрес `host/bucket/key` / `bucket.host/key`. Локальные хранилища обычно требуют path-style.
- **Stateless-сервис** — не хранит состояние между запросами у себя (ни сессий в памяти, ни файлов на диске), поэтому его можно свободно масштабировать и перезапускать.

## 15. gRPC и Protobuf
Подробно: [15-grpc.md](15-grpc.md)

- **RPC** (remote procedure call) — вызов функции на другом сервере так, будто она локальная.
- **gRPC** — RPC-фреймворк от Google поверх HTTP/2 с бинарной сериализацией Protobuf.
- **Protocol Buffers (Protobuf)** — бинарный формат сериализации и язык описания схемы.
- **.proto-файл** — описание сообщений (`message`) и сервисов (`service` с `rpc`-методами). По нему генерируется код клиента и сервера.
- **Номер поля** (field number) — `string name = 1;`. В бинарном формате передаётся номер, а не имя. Номера нельзя менять и переиспользовать — иначе сломается совместимость.
- **Обратная совместимость** (backward compatibility) — новые поля добавлять можно, удалять и менять типы существующих — нельзя (удалённые помечают `reserved`).
- **protoc / buf** — компилятор proto-файлов / современный инструмент для генерации, линтинга и проверки совместимости.
- **HTTP/2** — версия HTTP с мультиплексированием: много запросов в одном TCP-соединении, бинарные фреймы.
- **Unary RPC** — один запрос, один ответ.
- **Стриминг** — **server streaming** (поток ответов), **client streaming** (поток запросов), **bidirectional** (оба направления одновременно).
- **Metadata** — заголовки gRPC-вызова (аналог HTTP-заголовков): токен, request-id.
- **Interceptor** — middleware для gRPC: логирование, аутентификация, метрики, recover.
- **Дедлайн** (deadline) — момент, после которого вызов отменяется. Передаётся через context и распространяется по цепочке вызовов.
- **Коды статусов gRPC** — `OK`, `InvalidArgument`, `NotFound`, `AlreadyExists`, `PermissionDenied`, `Unauthenticated`, `Unavailable`, `DeadlineExceeded`, `Internal`.
- **grpc-gateway** — генерирует REST-прокси к gRPC-сервису по аннотациям в proto.
- **gRPC reflection** — сервер отдаёт описание своих методов, и инструменты (grpcurl, Postman) вызывают его без proto-файлов.

## 16. Observability
Подробно: [16-observability.md](16-observability.md)

- **Observability** (наблюдаемость) — возможность понять, что происходит внутри системы, по её внешним сигналам. Три столпа: **логи, метрики, трейсы**.
- **Структурный лог** (structured logging) — лог в виде пар ключ–значение (обычно JSON), а не свободного текста. В Go — `log/slog`, zap, zerolog.
- **Уровни логов** — DEBUG, INFO, WARN, ERROR.
- **Метрика** (metric) — числовое значение во времени: число запросов, задержка, память.
- **Prometheus** — система сбора метрик. Сама **забирает** (scrape) метрики с эндпоинта `/metrics` каждого сервиса. **PromQL** — язык запросов к метрикам.
- **Типы метрик** — **Counter** (только растёт: число запросов), **Gauge** (растёт и падает: число горутин, память), **Histogram** (распределение по корзинам: задержки, перцентили), Summary.
- **Лейблы** (labels) и **кардинальность** (cardinality) — измерения метрики (`method="GET"`, `status="200"`) / число их уникальных комбинаций. Нельзя класть в лейблы user_id или URL с id — метрики «взорвутся».
- **Grafana** — дашборды и алерты поверх Prometheus и других источников.
- **Алерт** (alert) — автоматическое уведомление, когда метрика выходит за порог.
- **RED** — метрики сервиса: **R**ate (запросов в секунду), **E**rrors (ошибки), **D**uration (длительность).
- **USE** — метрики ресурса: **U**tilization (загрузка), **S**aturation (очередь, насыщение), **E**rrors.
- **SLI / SLO / SLA** — измеряемый показатель качества (доля успешных запросов) / целевое значение (99.9%) / договорное обязательство перед клиентом.
- **Перцентиль** (percentile) — **p99 = 200 мс** значит: 99% запросов быстрее 200 мс. Среднее скрывает медленные хвосты, поэтому смотрят p95 и p99.
- **Распределённый трейсинг** (distributed tracing) — отслеживание одного запроса через все сервисы.
- **Trace и span** — весь путь запроса / один шаг в нём (HTTP-хендлер, запрос в БД, вызов другого сервиса), со временем начала и длительностью.
- **Context propagation** — передача trace id между сервисами в заголовках (стандарт W3C `traceparent`).
- **OpenTelemetry (OTel)** — открытый стандарт и SDK для трейсов, метрик и логов. **Jaeger** — система для просмотра трейсов.
- **pprof** — встроенный профилировщик Go: CPU, heap (память), goroutine, block, mutex.
- **Flame graph** — визуализация профиля: ширина блока — доля времени функции.
- **Health check** — эндпоинты `/healthz` (жив ли сервис) и `/readyz` (готов ли: подключены ли БД и зависимости).

## 17. Архитектура и system design
Подробно: [17-architecture.md](17-architecture.md)

- **Монолит** (monolith) — всё приложение в одном деплоимом сервисе. Проще разрабатывать и отлаживать.
- **Микросервисы** (microservices) — система из небольших независимых сервисов, каждый со своей БД. Масштабируются и деплоятся отдельно, но сложнее в эксплуатации.
- **Слоистая архитектура** (layered) — разделение на слои: **handler/transport** (HTTP, gRPC) → **service/usecase** (бизнес-логика) → **repository** (доступ к данным).
- **Clean / hexagonal architecture** — бизнес-логика в центре и не зависит от БД и фреймворков. Зависимости направлены **внутрь**, внешний мир подключается через интерфейсы (порты и адаптеры).
- **Dependency injection (DI)** — зависимости передаются объекту снаружи (через конструктор), а не создаются внутри. Упрощает тесты и замену реализаций.
- **cmd/ и internal/** — точки входа (`cmd/api/main.go`) / пакеты, которые нельзя импортировать из других модулей.
- **Горизонтальное и вертикальное масштабирование** — добавить больше экземпляров / сделать сервер мощнее.
- **Балансировщик нагрузки** (load balancer) — распределяет запросы между экземплярами сервиса.
- **API gateway** — единая точка входа для клиентов: маршрутизация, аутентификация, rate limit.
- **CDN** — сеть серверов, раздающих статический контент ближе к пользователю.
- **Репликация** (replication) — копии БД. Обычно один **leader** (принимает запись) и **followers / реплики** (чтение). **Лаг репликации** — отставание реплик.
- **Шардирование** (sharding) — горизонтальное разбиение данных между разными БД по ключу.
- **CAP-теорема** — при разделении сети (Partition) распределённая система выбирает между согласованностью (Consistency) и доступностью (Availability).
- **Eventual consistency** (согласованность в конечном счёте) — данные на всех узлах станут одинаковыми, но не мгновенно.
- **Таймаут** (timeout) — ограничение времени на операцию. Каждый сетевой вызов должен иметь таймаут.
- **Retry с jitter** — повтор с экспоненциальной задержкой и случайной добавкой, чтобы клиенты не повторяли одновременно.
- **Circuit breaker** (предохранитель) — после серии ошибок временно перестаёт вызывать проблемный сервис и сразу возвращает ошибку. Состояния closed → open → half-open.
- **Bulkhead** (переборка) — изоляция ресурсов (отдельные пулы для разных зависимостей), чтобы падение одной не утопило всё.
- **Graceful degradation** — при отказе части системы сервис продолжает работать с урезанной функциональностью.
- **Idempotency key** — уникальный ключ запроса от клиента. Повторный запрос с тем же ключом возвращает сохранённый результат и не выполняет операцию второй раз.
- **Saga** — распределённая транзакция из шагов в разных сервисах с **компенсирующими действиями** при ошибке. Хореография (через события) или оркестрация (координатор).
- **CQRS** — разделение моделей для записи (команды) и чтения (запросы).
- **Event sourcing** — хранить не текущее состояние, а последовательность событий, из которых оно получается.
- **SPOF** (single point of failure) — компонент, отказ которого роняет всю систему.
- **Latency и throughput** — задержка одного запроса / сколько запросов система обрабатывает в единицу времени (**RPS**).

## 18. OAuth 2.0 и OpenID Connect
Подробно: [18-oauth2-oidc.md](18-oauth2-oidc.md)

- **OAuth 2.0** — протокол делегирования доступа: приложение получает ограниченный доступ к ресурсам пользователя без его пароля.
- **OpenID Connect (OIDC)** — слой аутентификации поверх OAuth 2.0: добавляет ID token и данные о пользователе.
- **SSO** (single sign-on) — единый вход: один раз залогинился — доступ ко многим приложениям.
- **Роли OAuth** — **Resource Owner** (пользователь), **Client** (приложение), **Authorization Server** (выдаёт токены: Keycloak, Google), **Resource Server** (API).
- **Access token / refresh token / ID token** — токен для API / для обновления access token / для клиента, чтобы узнать, кто вошёл.
- **Scope** — запрошенные права: `openid profile email`, `tasks.read`.
- **Claim** — поле внутри токена: `sub` (id пользователя), `iss` (кто выдал), `aud` (для кого), `exp` (когда истекает).
- **Issuer** — адрес сервера авторизации, который выдал токен.
- **Discovery** — документ `/.well-known/openid-configuration` со всеми адресами и настройками провайдера.
- **JWKS** — набор публичных ключей провайдера для проверки подписи токенов. **kid** — id ключа в заголовке токена.
- **Authorization Code flow** — пользователь логинится у провайдера, приложение получает одноразовый code и обменивает его на токены на бэкенде.
- **PKCE** — защита code от перехвата: клиент генерирует секрет `code_verifier` и отправляет его хеш в начале, а сам секрет — при обмене.
- **state и nonce** — случайные значения для защиты от CSRF / от повторного использования ID token.
- **Redirect URI** — адрес, куда провайдер возвращает пользователя после входа. Должен быть заранее зарегистрирован.
- **Client Credentials flow** — сервис получает токен своим `client_id` и `client_secret`, без пользователя. Для общения сервис–сервис.
- **Client secret** — секрет приложения у сервера авторизации. Хранится только на бэкенде.
- **Keycloak** — open source сервер авторизации и управления пользователями.
- **BFF** (Backend for Frontend) — токены хранит сервер, а браузер получает только сессионную cookie.

## 19. Алгоритмы, сети, внутренности Go
Подробно: [19-cs-algorithms-internals.md](19-cs-algorithms-internals.md)

### Алгоритмы и структуры данных
- **Big-O** — оценка роста времени или памяти от размера входа: O(1), O(log n), O(n), O(n log n), O(n²).
- **Амортизированная сложность** — средняя стоимость операции на длинной серии. `append` в среднем O(1), хотя иногда копирует весь массив.
- **Хеш-таблица** (hash table) — поиск по ключу в среднем за O(1). **Коллизия** — разные ключи дали одинаковый хеш.
- **Стек и очередь** (stack, queue) — LIFO (последним пришёл — первым ушёл) и FIFO (первым пришёл — первым ушёл).
- **Связный список** (linked list) — элементы со ссылками на следующий. Вставка O(1), поиск O(n).
- **Куча / приоритетная очередь** (heap, priority queue) — быстро достаёт минимум или максимум: O(log n). В Go — `container/heap`.
- **Дерево** (tree), **бинарное дерево поиска** (BST) — иерархическая структура / слева меньше, справа больше.
- **Граф** (graph) — вершины и рёбра. **BFS** — обход в ширину (кратчайший путь в невзвешенном графе), **DFS** — в глубину.
- **Бинарный поиск** (binary search) — поиск в отсортированном массиве делением пополам: O(log n).
- **Два указателя** (two pointers) и **скользящее окно** (sliding window) — техники решения задач на массивах и строках за O(n).
- **Префиксные суммы** (prefix sums) — массив накопленных сумм для быстрого подсчёта суммы на отрезке.
- **Рекурсия** и **динамическое программирование** (DP) — функция вызывает саму себя / решение через сохранение ответов на подзадачи.

### Внутренности Go
- **Стек и куча** (stack vs heap memory) — стек: локальные переменные функции, освобождается сам. Куча: долгоживущие данные, которые убирает GC.
- **Escape analysis** — компилятор решает, где разместить переменную: если она «убегает» из функции (на неё ссылаются снаружи), то в куче. Смотреть: `go build -gcflags=-m`.
- **Аллокация** (allocation) — выделение памяти в куче. Меньше аллокаций — меньше работы GC.
- **GC** (сборщик мусора) — в Go конкурентный tri-color mark-and-sweep: работает параллельно с программой, с короткими паузами **STW** (stop-the-world). Не поколенческий и не перемещает объекты.
- **GOGC** — насколько может вырасти куча до следующей сборки (100 = вдвое).
- **Заголовок слайса** (slice header) — структура из трёх полей: указатель на массив, len, cap.
- **Устройство map** — хеш-таблица. С Go 1.24 реализована на Swiss tables (группы слотов с метаданными для быстрого поиска). Рост — с перераспределением элементов.
- **Устройство интерфейса** — пара «указатель на информацию о типе + указатель на данные» (`iface`, а для пустого интерфейса — `eface`).
- **Выравнивание** (alignment) — поля структуры выравниваются по размеру. Порядок полей влияет на размер структуры.
- **Горутина и поток ОС** — горутину планирует рантайм Go, поток — ядро ОС. Горутины дешевле в создании и переключении.

### Сети и ОС
- **Модель OSI / TCP/IP** — уровни сети: физический, канальный, сетевой (IP), транспортный (TCP/UDP), прикладной (HTTP, DNS).
- **IP-адрес и порт** — адрес машины в сети / номер приложения на ней.
- **TCP** — надёжный протокол с установкой соединения, порядком и повторной отправкой. **UDP** — без соединения и гарантий, но быстрее (DNS, видео, игры, QUIC).
- **Тройное рукопожатие** (three-way handshake) — SYN → SYN-ACK → ACK, установка TCP-соединения.
- **DNS** — система, превращающая домен (`google.com`) в IP-адрес.
- **TLS-рукопожатие** — согласование шифрования и проверка сертификата сервера перед обменом данными.
- **HTTP/1.1, HTTP/2, HTTP/3** — текстовый протокол, одно соединение на запрос в момент времени / бинарный с мультиплексированием / поверх QUIC (UDP).
- **Процесс и поток** — процесс: своя память. Поток: общая память внутри процесса. Переключение потоков дешевле.
- **Системный вызов** (syscall) — обращение программы к ядру ОС: чтение файла, сеть, создание процесса.
