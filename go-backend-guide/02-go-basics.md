## 0. Первая программа

```go
package main

import "fmt"

func main() {
    fmt.Println("Привет, Go!")
}
```

```bash
go run .              # скомпилировать во временную папку и запустить
go build -o hello .   # собрать бинарник ./hello
./hello
```

- Go — **компилируемый** язык: `go build` превращает исходники в один исполняемый файл без зависимостей. Его можно скопировать на сервер и запустить, ставить Go там не нужно.
- Компилятор строгий: **неиспользуемая переменная или импорт — ошибка компиляции**, а не предупреждение. Поначалу раздражает, потом спасает от мусора.
- Форматирование не обсуждается: весь Go-код в мире отформатирован `gofmt`. Табы для отступов, фигурная скобка на той же строке. Настрой редактор, чтобы форматировал при сохранении.
- Точки с запятой в конце строк не пишут: компилятор расставляет их сам. Из-за этого `{` **обязана** стоять на той же строке, что и `func`, `if`, `for`:
  ```go
  if x > 0 {   // правильно
  }

  if x > 0     // ошибка компиляции: после x > 0 компилятор поставит ;
  {
  }
  ```

## 1. Структура программы: файлы, пакеты, модули

Код в Go устроен в три уровня: **модуль** содержит **пакеты**, пакет состоит из **файлов**.

### Файл

Каждый `.go`-файл состоит из трёх частей в строгом порядке:

```go
package account            // 1. к какому пакету относится файл (обязательно, первой строкой)

import (                   // 2. что файл использует
    "errors"
    "fmt"

    "github.com/you/bank/internal/storage"
)

// 3. объявления: типы, функции, переменные, константы
type Account struct {
    owner   string
    balance int64
}

func New(owner string) *Account {
    return &Account{owner: owner}
}
```

Вне функций могут быть только объявления (`var`, `const`, `type`, `func`). Написать `fmt.Println(...)` на верхнем уровне файла нельзя.

### Пакет

**Пакет = папка.** Все `.go`-файлы в одной папке должны иметь одинаковое `package ...`. Компилятор видит их как одно целое: функция из `a.go` доступна в `b.go` той же папки без импорта.

```
internal/account/
├── account.go      // package account
├── history.go      // package account — видит всё из account.go
└── account_test.go // package account (или account_test — тесты «снаружи», см. файл 05)
```

- **Имя пакета** — коротко, в нижнем регистре, обычно совпадает с последней частью пути папки: `account`, `storage`. Не создавай `utils`, `common`, `helpers`: они превращаются в свалку.
- **Обращение снаружи** идёт через имя пакета: `account.New("ivan")`. Поэтому не повторяй имя пакета в именах: `account.New`, а не `account.NewAccount`.
- **Видимость определяет первая буква.** `New`, `Account` видны из других пакетов (экспортируются), `balance`, `validate` — только внутри своего. Слов `public` и `private` в Go нет.
- **Циклические импорты запрещены.** Если `account` импортирует `storage`, то `storage` уже не может импортировать `account` (`import cycle not allowed`). Решение — вынести общий тип в третий пакет или связать пакеты через интерфейс (файл 03).
- **`package main`** — особый пакет: из него собирается исполняемая программа, в нём должна быть `func main()`. Остальные пакеты — библиотеки, сами по себе они не запускаются.

### Модуль

**Модуль** — проект целиком: дерево пакетов с файлом `go.mod` в корне.

```
module github.com/fedos/bank        // путь модуля: префикс импортов всех твоих пакетов

go 1.25                             // минимальная версия языка; от неё зависит поведение (например, переменной цикла)

require (
    github.com/jackc/pgx/v5 v5.7.1                  // прямая зависимость
    github.com/jackc/puddle/v2 v2.2.2 // indirect   // зависимость твоей зависимости
)
```

- **Путь модуля** по соглашению совпадает с адресом репозитория: `github.com/<ник>/<проект>`. Пушить на GitHub необязательно, но так путь уникален, и другие смогут сделать `go get`.
- **Импорт своего пакета** = путь модуля + папка: `github.com/fedos/bank/internal/account`. Относительных импортов вроде `../account` нет.
- **`go.sum`** — контрольные суммы скачанных зависимостей, защита от подмены кода. Коммитится вместе с `go.mod`, руками не редактируется.
- **Версии** — semver: `v1.4.2`. Начиная с `v2` мажорная версия входит в путь импорта: `github.com/jackc/pgx/v5`. Для Go это разные пакеты.
- **Откуда качается код:** через прокси `proxy.golang.org` в общий кэш `~/go/pkg/mod`. Папки зависимостей внутри проекта (как `node_modules`) нет.
- Другие строки, которые встретятся в `go.mod`: `toolchain go1.25.3` (какую версию Go скачать для сборки, если установленная старее), `replace x => ../x` (подменить зависимость локальной копией), `tool ...` (инструменты разработки, запускаются через `go tool <имя>`).

```bash
go mod init github.com/fedos/bank      # создать go.mod
go get github.com/jackc/pgx/v5         # добавить зависимость (последняя версия)
go get github.com/jackc/pgx/v5@v5.6.0  # конкретная версия
go get -u ./...                        # обновить зависимости
go mod tidy                            # добавить недостающие и убрать неиспользуемые — запускай часто
go list -m all                         # все зависимости с версиями
go mod why github.com/x/y              # почему эта зависимость вообще есть
```

### Импорты

```go
import (
    "context"                                // стандартная библиотека — короткие пути
    "net/http"

    "github.com/go-chi/chi/v5"               // внешние модули

    "github.com/fedos/bank/internal/account" // свои пакеты
    pg "github.com/fedos/bank/internal/storage/postgres" // псевдоним
    _ "github.com/jackc/pgx/v5/stdlib"       // импорт ради побочного эффекта: пакет регистрирует драйвер в init()
)
```

Группы через пустую строку — соглашение. Инструмент `goimports` расставляет и группирует импорты сам, включи его в редакторе на сохранение.

### Порядок запуска программы

1. Инициализируются импортированные пакеты (рекурсивно, каждый ровно один раз).
2. В каждом пакете сначала вычисляются глобальные переменные, потом вызываются функции `init()` (их может быть несколько, даже в одном файле).
3. То же для `package main`.
4. Вызывается `main()`. Когда она возвращается, программа **завершается сразу**, даже если какие-то горутины ещё работают.

### Раскладка проекта

Маленькая утилита — всё в корне: `go.mod` + `main.go`. Сервис — стандартная раскладка Go-бэкенда (подробнее в файле 17):

```
tasks-api/
├── go.mod
├── go.sum
├── cmd/
│   ├── api/main.go          # точка входа: конфиг, сборка зависимостей, запуск
│   └── migrate/main.go      # второй бинарник из того же модуля
├── internal/                # весь код сервиса
│   ├── config/
│   ├── domain/              # типы Task, User, ошибки предметной области
│   ├── service/             # бизнес-логика
│   ├── storage/postgres/
│   └── transport/http/      # хендлеры, middleware, роутер
└── migrations/
```

- **`cmd/<имя>/`** — по папке на каждый бинарник, внутри тонкий `main.go`.
- **`internal/`** — особая папка: её пакеты компилятор разрешает импортировать **только изнутри этого модуля**.
- **`pkg/`** иногда используют для кода «для других проектов». Сервису он обычно не нужен.
- Не дроби проект заранее: начни с меньшего числа пакетов и выделяй новый, когда появилась понятная граница.

```bash
go run ./cmd/api                  # собрать и запустить конкретный бинарник
go build -o bin/api ./cmd/api
go test ./...                     # ./... = этот пакет и все вложенные
go vet ./...
```

> **Тонкости**
> - `found packages main (main.go) and utils (utils.go)` — в одной папке файлы с разным `package`.
> - `cannot find module providing package ...` — путь импорта не совпадает с `module` в `go.mod`, или забыл `go get` / `go mod tidy`.
> - `use of internal package not allowed` — импортируешь чужой `internal/`.
> - `cannot refer to unexported name` — обращаешься к имени с маленькой буквы из другого пакета.
> - `init()` нельзя вызвать вручную. Не прячь в нём важную логику: неявное поведение трудно отлаживать и тестировать.

**Задачи:** «Модуль из нескольких пакетов», «Порядок инициализации».

## 2. Переменные

```go
var age int              // объявление с нулевым значением: 0
var name string = "Ivan" // с типом и значением
var city = "Minsk"       // тип выведен из значения: string
count := 10              // короткое объявление — только внутри функций

var (                    // группа объявлений
    host = "localhost"
    port = 8080
)

a, b := 1, 2             // несколько сразу
a, b = b, a              // обмен значениями без временной переменной
```

- **Нулевые значения** (zero values): у каждого типа есть значение по умолчанию, неинициализированных переменных в Go нет. `0` для чисел, `""` для строк, `false` для `bool`, `nil` для указателей, слайсов, мап, каналов, функций и интерфейсов. Структура получает нулевые значения всех полей.
- **Хорошие типы делают нулевое значение полезным.** `var mu sync.Mutex`, `var sb strings.Builder`, `var buf bytes.Buffer` сразу готовы к работе без конструктора.
- **`:=` объявляет хотя бы одну новую переменную.** В `x, err := f()` можно переиспользовать уже объявленный `err`, если `x` новая. Если новых переменных нет — ошибка `no new variables on left side of :=`.
- **Пустой идентификатор `_`** — выбросить ненужное значение: `_, err := f()`, `for _, v := range s`.
- **Неиспользуемая локальная переменная — ошибка компиляции.** Глобальные (уровня пакета) можно не использовать.
- **Область видимости** (scope) — блок в фигурных скобках. Переменная из `if`, `for`, `switch` видна только внутри.

### Затенение (shadowing)

`:=` во вложенном блоке создаёт **новую** переменную, даже если снаружи есть такая же. Внешняя при этом не меняется:

```go
var user *User
var err error
if id > 0 {
    user, err := findUser(id) // НОВЫЕ user и err, живут только внутри if
    _, _ = user, err
}
fmt.Println(user, err) // <nil> <nil> — внешние не изменились
```

Исправление — `=` вместо `:=`, если переменные уже объявлены снаружи. Стандартный `go vet` этого не ловит. Нужен анализатор `shadow` или `golangci-lint` с проверкой `govet: shadow`.

> **Тонкости**
> - Чаще всего так теряют `err`: проверили внутренний, а наружу вернули внешний `nil`.
> - Можно затенить даже имя пакета или встроенную функцию: `len := 5` сделает `len()` недоступной в этом блоке. Не называй переменные `len`, `new`, `string`, `copy`, `error`.

**Задачи:** «Найди баг» в разделе «Затенение и переменная цикла».

## 3. Базовые типы и преобразования

| Тип | Что это | Нулевое значение |
|---|---|---|
| `bool` | `true` / `false` | `false` |
| `int`, `int8`, `int16`, `int32`, `int64` | целые со знаком. `int` — 64 бита на 64-битных системах | `0` |
| `uint`, `uint8` … `uint64` | целые без знака | `0` |
| `byte` | синоним `uint8` | `0` |
| `rune` | синоним `int32`, один символ Unicode | `0` |
| `float32`, `float64` | числа с плавающей точкой. Используй `float64` | `0` |
| `complex64`, `complex128` | комплексные числа (почти не нужны) | `0` |
| `string` | неизменяемая последовательность байт | `""` |

В обычном коде бери `int` для целых, `float64` для дробных, `int64` — для того, что хранится в БД или передаётся по сети (id, деньги в копейках, время в миллисекундах).

### Преобразования только явные

```go
i := 42
f := float64(i)      // int → float64

big := 300
u := uint8(big)      // 44: старшие биты отбрасываются молча
fl := 3.99
n := int(fl)         // 3: дробная часть отбрасывается, не округляется
// uint8(300) и int(3.99) с константами не скомпилируются: компилятор видит потерю данных

var a int32 = 5
var b int64 = 10
// c := a + b        // ошибка: разные типы (mismatched types int32 and int64)
c := int64(a) + b
```

Строки и числа преобразуются **не** через `string()`, а через пакет `strconv` (раздел 21):
```go
s := strconv.Itoa(42)          // "42"
n, err := strconv.Atoi("42")   // 42, nil
x := string(rune(65))          // "A" — так получают символ по коду, а не число в строку
```

### Целые числа

```go
fmt.Println(7/2, -7/2, 7%3, -7%3) // 3 -3 1 -1: деление отбрасывает дробь к нулю, знак остатка = знак делимого
fmt.Println(7.0 / 2)              // 3.5: если нужна дробь, хотя бы один операнд float

var x int8 = 127
x++
fmt.Println(x)                    // -128: переполнение во время выполнения происходит молча

fmt.Println(math.MaxInt64, math.MinInt64)
```

- Деление целого на ноль-переменную — **panic** во время выполнения. Деление на константу 0 — ошибка компиляции.
- Деление `float64` на ноль даёт `+Inf`, `-Inf` или `NaN`, без паники. `NaN != NaN`.

### Числа с плавающей точкой

```go
a, b := 0.1, 0.2
fmt.Println(a+b)          // 0.30000000000000004
fmt.Println(a+b == 0.3)   // false
```

Двоичная дробь не может точно хранить 0.1. Поэтому:
- **деньги никогда не хранят во float** — только целые копейки в `int64` (или специальные decimal-библиотеки);
- float сравнивают с допуском: `math.Abs(a-b) < 1e-9`.

### Свои типы и алиасы

```go
type Celsius float64        // НОВЫЙ тип на основе float64
type UserID int64

var t Celsius = 36.6
var f float64 = t           // ошибка: Celsius и float64 — разные типы
var f2 float64 = float64(t) // ok

type MyInt = int            // АЛИАС: просто второе имя того же типа (используется редко)
```

Свой тип нужен, чтобы компилятор не дал перепутать сущности (передать `UserID` туда, где ждут `OrderID`) и чтобы повесить на тип методы (раздел 17).

> **Тонкости**
> - `int` и `int64` — разные типы, даже если оба 64-битные.
> - Конвертация в меньший тип и из float в int молча теряет данные. Компилятор не предупредит.
> - `len()` возвращает `int`, поэтому индексы и счётчики делай `int`, иначе придётся конвертировать.

**Задачи:** «Предскажи вывод: числа».

## 4. Константы и iota

```go
const Pi = 3.14159
const (
    MaxRetries = 3
    Timeout    = 5 * time.Second
)
```

Константы вычисляются **на этапе компиляции**. Это могут быть только числа, строки, руны и `bool`. Константного слайса или структуры не бывает.

### Константы без типа

`const Pi = 3.14159` — константа **без типа** (untyped). Она хранится с произвольной точностью и получает тип только там, где используется:

```go
const big = 1 << 100        // нормально: такой константе int не нужен
fmt.Println(big >> 98)      // 4 — результат влезает в int
// fmt.Println(big)         // ошибка компиляции: constant overflows int

const x = 5
var f float64 = x           // ok: x станет float64
var i int = x               // ok: x станет int

var r float64 = 1 / 3       // 0 ! 1 и 3 — целые константы, деление целочисленное
var r2 float64 = 1.0 / 3    // 0.333...

fmt.Println(0.1+0.2 == 0.3) // true ! константы складываются точно, без ошибки float
```

Типизированная константа: `const Port int = 8080` — ведёт себя как `int`.

### iota

`iota` — счётчик внутри блока `const`: 0 на первой строке, дальше растёт на 1. Если у строки нет выражения, повторяется предыдущее.

```go
type Weekday int

const (
    Sunday Weekday = iota // 0
    Monday                // 1
    Tuesday               // 2
)

const (
    _  = iota             // пропустить 0
    KB = 1 << (10 * iota) // 1 << 10 = 1024
    MB                    // 1 << 20
    GB                    // 1 << 30
)

type Perm uint8
const (
    Read  Perm = 1 << iota // 1  (001)
    Write                  // 2  (010)
    Exec                   // 4  (100)
)
p := Read | Write          // 3 (011)
canWrite := p&Write != 0   // true
```

### Перечисления со String()

В Go нет `enum`, вместо него — свой тип + `iota` + метод `String()`:

```go
type Status int

const (
    StatusNew Status = iota
    StatusPaid
    StatusShipped
)

func (s Status) String() string {
    switch s {
    case StatusNew:
        return "new"
    case StatusPaid:
        return "paid"
    case StatusShipped:
        return "shipped"
    }
    return fmt.Sprintf("Status(%d)", int(s))
}

fmt.Println(StatusPaid) // paid — fmt сам вызывает String()
```

> **Тонкости**
> - Ничто не мешает написать `Status(42)`, поэтому значения из внешнего мира (JSON, БД) проверяй.
> - Часто первое значение делают «неизвестным» (`StatusUnknown = iota`), чтобы нулевое значение не выглядело как настоящий статус.
> - Внутри `String()` не вызывай `fmt.Sprintf("%v", s)` с тем же значением: это бесконечная рекурсия. Конвертируй в `int(s)`.

**Задачи:** «Перечисление статусов заказа», «Права доступа на флагах».

## 5. Операторы

| Группа | Операторы | Комментарий |
|---|---|---|
| Арифметика | `+ - * / %` | `+` склеивает строки |
| Инкремент | `x++`, `x--` | это **инструкция**, а не выражение: `y := x++` и `++x` не компилируются |
| Сравнение | `== != < <= > >=` | сравнивать можно только значения одного типа |
| Логика | `&& \|\| !` | ленивые: `a && b` не вычисляет `b`, если `a == false` |
| Биты | `& \| ^ &^ << >>` | `&^` — «И-НЕ» (сбросить биты), `^x` — побитовое отрицание |
| Присваивание | `= += -= *= /= %= <<= &= …` | |
| Адрес и значение | `&x`, `*p` | раздел 11 |

- **Тернарного оператора** `a ? b : c` в Go нет. Пиши `if`.
- Ленивость `&&` используют для защиты: `if p != nil && p.Age > 18`.
- Приоритет как в математике, но лучше ставь скобки, если сомневаешься: `a & b == 0` читается неочевидно.

## 6. Управление потоком: if, for, switch

### if

```go
if x > 10 {
    fmt.Println("большое")
} else if x > 0 {
    fmt.Println("положительное")
} else {
    fmt.Println("ноль или меньше")
}

// короткое объявление в условии: v и ok видны только внутри if/else
if v, ok := cache[key]; ok {
    return v
}

if err := save(); err != nil {
    return err
}
```

- Скобки вокруг условия не пишут, фигурные скобки обязательны всегда, даже для одной строки.
- Условие — только `bool`. `if x` для числа или `if ptr` для указателя не компилируются: пиши `if x != 0`, `if ptr != nil`.
- Стиль Go — **ранний выход** (early return): сначала отсечь ошибки и особые случаи, основная логика без отступа. Длинные цепочки `else` после `return` не нужны.

### for — единственный цикл

```go
for i := 0; i < 5; i++ { }   // классический

for n < 100 { n *= 2 }       // как while

for { break }                // бесконечный, выход через break или return

for i := range 5 { }         // Go 1.22+: i = 0, 1, 2, 3, 4

for i, v := range []string{"a", "b"} { } // индекс и копия элемента
for i := range s { }          // только индекс
for _, v := range s { }       // только значение

for k, v := range m { }       // мапа: ключ и значение, порядок случайный
for i, r := range "привет" { } // строка: индекс БАЙТА и руна (раздел 15)
for v := range ch { }         // канал: до закрытия (файл 04)
for v := range seq { }        // итератор-функция (раздел 19)
```

- `break` — выйти из цикла, `continue` — перейти к следующей итерации.
- **Метки** — выйти из внешнего цикла:
  ```go
  outer:
      for _, row := range grid {
          for _, cell := range row {
              if cell == target {
                  break outer // выход из обоих циклов
              }
          }
      }
  ```

### Переменная цикла (Go 1.22+)

С Go 1.22 каждая итерация получает **свою** копию переменной цикла. Раньше переменная была одна на весь цикл, и замыкания или указатели, сохранённые в цикле, видели последнее значение:

```go
var funcs []func()
for i := 0; i < 3; i++ {
    funcs = append(funcs, func() { fmt.Print(i) })
}
for _, f := range funcs { f() } // Go 1.22+: 012. До 1.22: 333
```

Поведение включает строка `go 1.22` (или новее) в `go.mod`, а не установленная версия Go. В старых проектах и статьях ещё встретится «лечение» `i := i` внутри цикла: сейчас оно не нужно.

### switch

```go
switch day {
case "sat", "sun":              // несколько значений в одном case
    fmt.Println("выходной")
case "fri":
    fmt.Println("почти")
    fallthrough                 // явно перейти в следующий case (без проверки условия)
case "mon", "tue", "wed", "thu":
    fmt.Println("рабочий")
default:
    fmt.Println("неизвестно")
}

switch {                        // без выражения — замена цепочки if-else
case score >= 90:
    grade = "A"
case score >= 75:
    grade = "B"
default:
    grade = "C"
}

switch n := len(items); {       // с коротким объявлением
case n == 0:
case n > 100:
}
```

- `break` после каждого `case` писать **не надо**: в Go нет «проваливания» по умолчанию, выполняется только один case.
- `case` проверяются сверху вниз, выполняется первый подходящий.
- Есть ещё `switch v := x.(type)` для интерфейсов — в файле 03.

> **Тонкости**
> - `break` внутри `switch` или `select` выходит из `switch`, а **не** из окружающего `for`. Чтобы выйти из цикла, нужна метка: `break loop`.
> - `for _, v := range users { v.Age++ }` не изменит слайс: `v` — копия элемента. Меняй через индекс: `users[i].Age++`.
> - Выражение в `range` вычисляется один раз до начала цикла. `append` к слайсу внутри цикла по нему не продлевает цикл.
> - Удалять ключи мапы во время `range` по ней можно. Добавленные во время обхода ключи могут попасть или не попасть в обход.
> - `goto` в Go есть, но в обычном коде не используется.

**Задачи:** «FizzBuzz+», «Переменная цикла до и после Go 1.22», «Метки».

## 7. Функции

```go
func add(a, b int) int {            // параметры одного типа можно сгруппировать
    return a + b
}

func divide(a, b float64) (float64, error) { // несколько результатов
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}

q, err := divide(10, 2)
_, err = divide(1, 0)               // ненужный результат — в _
```

- Всё передаётся **по значению**: функция получает копию аргумента. Чтобы функция меняла переменную вызывающего, передают указатель (раздел 11).
- Перегрузки функций (две `add` с разными параметрами), параметров по умолчанию и именованных аргументов в Go **нет**. Вместо них — разные имена (`ParseInt`, `ParseFloat`) или структура параметров:
  ```go
  type ServerConfig struct {
      Port    int
      Timeout time.Duration
  }
  func NewServer(cfg ServerConfig) *Server { ... }
  NewServer(ServerConfig{Port: 8080}) // Timeout будет нулевым — обработай это внутри
  ```

### Именованные результаты

```go
func split(sum int) (x, y int) { // x и y — обычные переменные, изначально 0
    x = sum * 4 / 9
    y = sum - x
    return                       // «голый» return вернёт текущие x и y
}
```

Именованные результаты полезны для документации (`(user User, found bool)`) и в связке с `defer` (раздел 8). Голый `return` в длинной функции читается плохо — пиши значения явно.

### Вариадические функции

```go
func sum(nums ...int) int {   // внутри nums — это []int
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

sum()            // 0, nums == nil
sum(1, 2, 3)     // 6
s := []int{4, 5}
sum(s...)        // распаковать готовый слайс
```

`fmt.Println(a ...any)` устроена так же. Вариадический параметр может быть только последним.

### Функции — это значения

```go
var op func(int, int) int     // тип «функция двух int, возвращающая int», нулевое значение nil
op = add
fmt.Println(op(2, 3))         // 5

ops := map[string]func(float64, float64) float64{
    "+": func(a, b float64) float64 { return a + b },
    "*": func(a, b float64) float64 { return a * b },
}
fmt.Println(ops["*"](3, 4))   // 12

type Middleware func(http.Handler) http.Handler // именованный тип функции

func apply(nums []int, f func(int) int) []int { // функция как параметр
    out := make([]int, 0, len(nums))
    for _, n := range nums {
        out = append(out, f(n))
    }
    return out
}
apply([]int{1, 2, 3}, func(n int) int { return n * n }) // анонимная функция на месте
```

### Замыкания

Анонимная функция **захватывает переменные** из окружения — не копию значения, а саму переменную:

```go
func counter() func() int {
    c := 0
    return func() int {
        c++              // c живёт, пока жива возвращённая функция
        return c
    }
}

next := counter()
fmt.Println(next(), next(), next()) // 1 2 3
other := counter()
fmt.Println(other())                // 1 — у каждого вызова counter() своя c

x := 1
show := func() { fmt.Println(x) }
x = 2
show()                              // 2: замыкание видит текущее значение x
```

Замыкания используют для генераторов, middleware, отложенных действий, кэширования (`Memoize`), «настроенных» функций (`makeMultiplier(3)`).

> **Тонкости**
> - Вызов nil-функции — panic. Функции можно сравнивать только с `nil`, две функции между собой — нельзя.
> - Слайс, переданный через `s...`, **не копируется**: функция получит тот же массив и может изменить элементы вызывающего.
> - Рекурсия работает как обычно, стек горутины растёт сам. Но хвостовой оптимизации нет, так что очень глубокая рекурсия (миллионы уровней) упрётся в лимит стека.
> - Функцию можно объявить и сразу вызвать: `func() { ... }()`. Часто используется с `defer` и `go`.

**Задачи:** «Функции как значения».

## 8. defer

`defer` откладывает вызов до момента, когда **окружающая функция** завершится — через `return`, конец тела или панику:

```go
func readConfig(path string) ([]byte, error) {
    f, err := os.Open(path)
    if err != nil {
        return nil, err
    }
    defer f.Close()       // закроется при любом выходе из функции

    return io.ReadAll(f)
}
```

Правило: получил ресурс — сразу, следующей строкой после проверки ошибки, поставь `defer` на его освобождение (`Close`, `Unlock`, `cancel`, `Rollback`). Так ресурс не утечёт, даже если позже в функции появится новый `return`.

### Три правила defer

**1. Порядок LIFO** — последний отложенный выполняется первым:
```go
defer fmt.Println(1)
defer fmt.Println(2)
defer fmt.Println(3)
// выведет 3, 2, 1
```

**2. Аргументы вычисляются сразу**, в момент `defer`, а не при выполнении:
```go
x := 1
defer fmt.Println("x =", x)          // запомнит 1
defer func() { fmt.Println("x в замыкании =", x) }() // увидит итоговое значение
x = 100
// x в замыкании = 100
// x = 1
```

**3. defer может изменить именованный результат**, потому что выполняется после `return`, но до возврата управления:
```go
func double() (result int) {
    defer func() { result *= 2 }()
    return 3 // result = 3, потом defer: result = 6
}
```

Это используют, чтобы не потерять ошибку закрытия файла, в который писали:
```go
func writeFile(path string, data []byte) (err error) {
    f, err := os.Create(path)
    if err != nil {
        return err
    }
    defer func() {
        if cerr := f.Close(); cerr != nil && err == nil {
            err = cerr // основная операция прошла, но Close упал — вернём его ошибку
        }
    }()
    _, err = f.Write(data)
    return err
}
```

> **Тонкости**
> - **defer в цикле** выполнится в конце **функции**, а не итерации. Открыв в цикле 10 000 файлов с `defer f.Close()`, ты держишь их все открытыми до выхода из функции. Решение — вынести тело цикла в отдельную функцию.
> - `os.Exit()` и `log.Fatal()` завершают программу **без** выполнения `defer`.
> - `defer` выполняется и при панике — на этом построен `recover` (раздел 10).
> - Ошибку из `defer f.Close()` молча теряют. Для файлов, открытых на чтение, это нормально. Для записи — обработай, как в примере выше.

**Задачи:** «Предскажи вывод: defer», «defer на практике».

## 9. Ошибки: первое знакомство

В Go нет исключений. Ошибка — обычное значение типа `error`, которое функция возвращает **последним** результатом:

```go
n, err := strconv.Atoi(input)
if err != nil {
    return fmt.Errorf("parse age %q: %w", input, err) // добавить контекст и вернуть выше
}
// здесь n можно использовать
```

- `err == nil` — успех. Не `nil` — ошибка, и остальные результаты обычно использовать нельзя.
- Проверяй ошибку **сразу** после вызова. Игнорировать (`n, _ := ...`) можно, только если ты точно знаешь, что ошибки быть не может.
- Создать ошибку: `errors.New("not found")` или `fmt.Errorf("user %d: not found", id)`.
- `%w` в `fmt.Errorf` **оборачивает** исходную ошибку: к ней можно добраться через `errors.Is` / `errors.As`.
- Ошибку либо обрабатывают (логируют, отдают пользователю, повторяют), либо возвращают выше с контекстом. Делать и то и другое (залогировать **и** вернуть) — плохо: в логах будут дубли.

Подробно: свои типы ошибок, sentinel-ошибки, `errors.Is/As`, ловушка nil-интерфейса — в файле 03.

## 10. panic и recover

`panic` — аварийная остановка: текущая функция прерывается, выполняются все `defer` вверх по стеку вызовов, и если никто не перехватил, программа падает со стектрейсом.

Рантайм сам паникует при:
- записи в nil-мапу;
- выходе за границы слайса или массива (`index out of range`);
- разыменовании nil-указателя;
- неудачном приведении типа `x.(T)` без `ok`;
- делении целого на ноль;
- закрытии уже закрытого канала, отправке в закрытый канал.

`recover()` останавливает панику и возвращает переданное в `panic` значение, но **только** если вызван прямо внутри отложенной функции:

```go
func safeDivide(a, b int) (res int, err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("recovered: %v", r)
        }
    }()
    return a / b, nil
}

fmt.Println(safeDivide(10, 0)) // 0 recovered: runtime error: integer divide by zero
```

Когда **уместно** паниковать:
- ошибка программиста, которой не может быть при правильном коде (невозможная ветка `switch`);
- неудача при старте, без которой программа бессмысленна: функции `regexp.MustCompile`, `template.Must` паникуют при неверном шаблоне.

Во всех остальных случаях возвращай `error`. HTTP-серверы ставят `recover` в middleware, чтобы паника в одном запросе не уронила весь сервис (стандартный `net/http` делает это сам).

> **Тонкости**
> - **Паника в другой горутине так не перехватывается.** `recover` работает только в той горутине, где случилась паника. Необработанная паника в любой горутине роняет весь процесс. Поэтому в каждой запускаемой горутине, которая может паниковать, нужен свой `defer recover()`.
> - `recover()` вне `defer` или во вложенной в defer функции возвращает `nil` и ничего не останавливает.
> - В `panic` можно передать что угодно, но лучше `error`: тогда после `recover` его можно обернуть через `%w`.

**Задачи:** «SafeCall», «Паника в горутине».

## 11. Указатели

Указатель хранит **адрес** значения в памяти.

```go
x := 10
p := &x          // p имеет тип *int — «указатель на int»
fmt.Println(*p)  // 10 — разыменование: значение по адресу
*p = 20          // меняем значение по адресу
fmt.Println(x)   // 20

var q *int       // нулевое значение указателя — nil
// fmt.Println(*q) // panic: nil pointer dereference

r := new(int)    // выделить память под int и вернуть указатель, *r == 0
```

### Зачем указатели

**1. Чтобы функция могла изменить значение вызывающего:**
```go
func resetValue(n int)    { n = 0 }  // меняет копию
func resetPointer(n *int) { *n = 0 } // меняет оригинал

a := 5
resetValue(a)    // a == 5
resetPointer(&a) // a == 0
```

**2. Чтобы не копировать большие структуры** при каждом вызове.

**3. Чтобы выразить «значения нет»**: `nil` отличается от нулевого значения. Например, в PATCH-запросе `*string` позволяет отличить «поле не передали» (`nil`) от «передали пустую строку» (`""`).

### Указатели на структуры

```go
type User struct{ Name string; Age int }

u := &User{Name: "Ivan"} // сразу указатель на новую структуру — так делают чаще всего
u.Age = 20               // автоматическое разыменование: то же, что (*u).Age = 20
```

> **Тонкости**
> - **Вернуть указатель на локальную переменную безопасно**: `return &User{...}`. Компилятор сам перенесёт её в кучу (escape analysis, файл 19). В C так делать нельзя, в Go — нормальная практика.
> - Арифметики указателей нет: `p + 1` не скомпилируется.
> - Слайсы, мапы, каналы уже содержат внутри указатели на данные. Указатель на слайс или мапу нужен редко.
> - Указатели сравниваются через `==`: равны, если указывают на одно и то же место.
> - Перед разыменованием указателя, который может быть `nil`, проверяй его: `if u != nil`.
> - Указатель — не «ускорение по умолчанию». Для маленьких структур копирование дешёвое, а указатели добавляют работы сборщику мусора.

## 12. Массивы

```go
var a [3]int               // [0 0 0]
b := [3]string{"a", "b", "c"}
c := [...]int{1, 2, 3, 4}  // длину посчитает компилятор: [4]int
fmt.Println(len(c), c[0])
```

- **Длина — часть типа**: `[3]int` и `[4]int` — разные типы. Длина задаётся константой и не меняется.
- **Массив — значение**: присваивание и передача в функцию копируют **все** элементы.
  ```go
  x := [3]int{1, 2, 3}
  y := x       // полная копия
  y[0] = 100
  fmt.Println(x, y) // [1 2 3] [100 2 3]
  ```
- Массивы можно сравнивать через `==` и использовать как ключ мапы.
- В обычном коде массивы почти не используют напрямую — работают со **слайсами**. Массив встречается там, где размер фиксирован по смыслу: `[16]byte` для UUID, `[32]byte` для хеша SHA-256, ключ мапы `[2]int` для координат.

## 13. Слайсы

Слайс — главная структура данных Go и **самая частая тема вопросов про основы на собеседованиях**. Разберись в этом разделе до конца.

### Что такое слайс

Слайс — маленькая структура из трёх полей, которая смотрит на кусок массива:

```
s := []int{10, 20, 30, 40, 50}

слайс s                      массив в памяти (backing array)
┌─────────┐                  ┌────┬────┬────┬────┬────┐
│ ptr  ───┼────────────────▶ │ 10 │ 20 │ 30 │ 40 │ 50 │
│ len = 5 │                  └────┴────┴────┴────┴────┘
│ cap = 5 │
└─────────┘
```

- **ptr** — указатель на первый элемент слайса в массиве;
- **len** — сколько элементов видно через слайс (`len(s)`);
- **cap** — сколько элементов есть в массиве от `ptr` до конца (`cap(s)`).

### Создание

```go
var a []int                  // nil-слайс: ptr = nil, len = 0, cap = 0
b := []int{}                 // пустой, но не nil
c := []int{1, 2, 3}          // литерал: len = 3, cap = 3
d := make([]int, 3)          // [0 0 0], len = 3, cap = 3
e := make([]int, 0, 10)      // [], len = 0, cap = 10 — место заранее выделено
```

Если заранее известно, сколько будет элементов, создавай `make([]T, 0, n)` и добавляй через `append`: не будет лишних перевыделений памяти.

### Срезы (slicing)

```go
s := []int{10, 20, 30, 40, 50}
t := s[1:3]       // [20 30]: с индекса 1 включительно до 3 не включительно
fmt.Println(len(t), cap(t)) // 2 4 — cap считается до конца исходного массива

s[:2]   // [10 20] — с начала
s[3:]   // [40 50] — до конца
s[:]    // весь слайс
```

```
s ──▶ ┌────┬────┬────┬────┬────┐
      │ 10 │ 20 │ 30 │ 40 │ 50 │
      └────┴────┴────┴────┴────┘
t ───────────▶ ↑ len = 2 (20, 30), cap = 4 (20…50)
```

**`t` — не копия.** Он смотрит на тот же массив, поэтому `t[0] = 99` изменит и `s[1]`.

Через срез можно «расширить» слайс в пределах cap: `t[:4]` даст `[20 30 40 50]`, хотя у самого `t` длина 2. За cap выйти нельзя — panic.

### append

```go
s := []int{1, 2, 3}
s = append(s, 4)          // добавить один
s = append(s, 5, 6)       // несколько
s = append(s, other...)   // другой слайс целиком
```

Как работает `append`:
1. Если `len < cap` — новый элемент пишется в **тот же массив** на место `len`, возвращается слайс с `len + 1`.
2. Если `len == cap` — выделяется **новый массив побольше**, туда копируются старые элементы и добавляется новый. Для небольших слайсов ёмкость примерно удваивается, для больших (от 256 элементов) рост плавно замедляется примерно до ×1,25.

Отсюда главное правило: **всегда присваивай результат `append`**: `s = append(s, x)`. Без присваивания добавленный элемент потеряется, а после перевыделения старый `s` будет смотреть на старый массив.

```go
a := make([]int, 3, 4) // [0 0 0], свободно одно место
b := append(a, 1)      // поместилось: b и a смотрят на один массив
b[0] = 100
fmt.Println(a[0])      // 100 — изменение видно через a!

c := append(b, 2)      // в b места нет (len 4 == cap 4): новый массив
c[0] = -1
fmt.Println(b[0])      // 100 — c уже живёт отдельно
```

Пока не знаешь точно, хватит ли ёмкости, считай, что после `append` новый слайс **может** быть связан со старым, а может и не быть. Не полагайся ни на то, ни на другое.

### Полное выражение среза s[low:high:max]

Третий индекс ограничивает cap нового слайса: `cap = max - low`. Тогда первый же `append` создаст новый массив и не перезапишет чужие данные:

```go
s := []int{1, 2, 3, 4, 5}
safe := s[0:2:2]          // len 2, cap 2
safe = append(safe, 99)   // новый массив
fmt.Println(s)            // [1 2 3 4 5] — не тронут
```

Используй, когда отдаёшь кусок своего слайса наружу.

### copy и клонирование

```go
src := []int{1, 2, 3}
dst := make([]int, len(src))
n := copy(dst, src)       // копирует min(len(dst), len(src)) элементов, возвращает их число

clone := slices.Clone(src) // проще: новый слайс с копией данных

alias := src              // НЕ копия: тот же массив
```

### Слайс в функции

Функция получает **копию заголовка** (ptr, len, cap), но массив под ним общий:

```go
func setFirst(s []int) { s[0] = 100 }        // изменит данные вызывающего
func addItem(s []int)  { s = append(s, 1) }  // вызывающий НЕ увидит новый элемент:
                                             // у него свой len, а при перевыделении — и свой массив

func addItemOK(s []int) []int { return append(s, 1) } // правильно: вернуть результат
items = addItemOK(items)
```

### nil-слайс и пустой слайс

```go
var a []int   // nil
b := []int{}  // не nil
```

Ведут себя одинаково почти везде: `len == 0`, по обоим можно делать `range` и `append`. Разница:
- `a == nil` → `true`, `b == nil` → `false`;
- в JSON nil-слайс превращается в `null`, пустой — в `[]`. Для API это важно: фронтенд может ждать массив.

Функцию, которая возвращает «ничего не нашлось», лучше писать так, чтобы вызывающий проверял `len(s) == 0`, а не `s == nil`.

### Многомерные слайсы

```go
grid := make([][]int, rows)
for i := range grid {
    grid[i] = make([]int, cols) // каждую строку создаём отдельно
}
grid[1][2] = 5
```

### Удаление, вставка, поиск

Пакет `slices` (стандартная библиотека) закрывает большинство задач:

```go
s := []int{3, 1, 4, 1, 5}

slices.Sort(s)                          // [1 1 3 4 5]
slices.Contains(s, 4)                   // true
slices.Index(s, 4)                      // 3 (или -1)
s = slices.Insert(s, 1, 9)              // вставить 9 на позицию 1
s = slices.Delete(s, 0, 2)              // удалить элементы [0, 2)
s = slices.DeleteFunc(s, func(n int) bool { return n%2 == 0 }) // удалить чётные
s = slices.Compact(s)                   // убрать подряд идущие дубли
slices.Reverse(s)
m := slices.Max(s)                      // panic на пустом слайсе
slices.Equal(a, b)                      // сравнение содержимого

slices.SortFunc(users, func(a, b User) int {
    return cmp.Compare(a.Age, b.Age)    // <0, если a раньше b
})
```

Классическая идиома удаления элемента `i` с сохранением порядка, которую ты встретишь в любом коде:
```go
s = append(s[:i], s[i+1:]...) // сдвигает хвост влево — меняет исходный массив!
```

> **Тонкости**
> - `for _, v := range s { v *= 2 }` не изменит слайс: `v` — копия. Меняй через индекс: `s[i] *= 2`.
> - Слайсы нельзя сравнивать через `==` (кроме сравнения с `nil`) и нельзя использовать как ключ мапы. Для сравнения есть `slices.Equal`.
> - **Утечка памяти через подслайс.** `small := huge[:10]` держит в памяти весь огромный массив `huge`, пока жив `small`. Если нужен маленький кусок надолго — `slices.Clone(huge[:10])`.
> - Индекс за пределами `len` — panic `index out of range`. Проверяй длину перед `s[0]`.
> - `append` к слайсу, полученному срезом, может молча перезаписать элементы исходного слайса — см. пример выше и задачу «Предскажи вывод: слайсы в функциях».

**Задачи:** «Предскажи вывод» (первая), «Предскажи вывод: слайсы в функциях», «Утилиты для слайсов», «Массив — это значение», «Стек и очередь», «Матрицы».

## 14. Мапы

Мапа — хеш-таблица «ключ → значение»: поиск, вставка и удаление в среднем за O(1).

```go
ages := map[string]int{       // литерал
    "ivan": 20,
    "anna": 25,               // запятая после последнего элемента обязательна
}
scores := make(map[string]int)     // пустая мапа
hint := make(map[string]int, 1000) // с подсказкой размера: меньше перевыделений

ages["petr"] = 30             // добавить или перезаписать
fmt.Println(ages["ivan"])     // 20
fmt.Println(ages["nobody"])   // 0 — для отсутствующего ключа вернётся нулевое значение

age, ok := ages["nobody"]     // «comma ok»: ok == false, если ключа нет
if !ok {
    fmt.Println("нет такого")
}

delete(ages, "anna")          // удалить; если ключа нет — ничего не произойдёт
fmt.Println(len(ages))        // число ключей

for name, age := range ages { // порядок обхода СЛУЧАЙНЫЙ
    fmt.Println(name, age)
}
```

### Когда отличать «нет ключа» от нулевого значения

`m[k]` возвращает `0`, `""`, `false` и для отсутствующего ключа, и для ключа со значением 0. Если разница важна — используй `v, ok := m[k]`. Если не важна (счётчики), нулевое значение очень удобно:

```go
counts := map[string]int{}
for _, w := range words {
    counts[w]++                 // отсутствующий ключ = 0, сразу +1
}

groups := map[string][]string{}
for _, u := range users {
    groups[u.City] = append(groups[u.City], u.Name) // append к nil-слайсу работает
}
```

### Порядок обхода

Порядок `range` по мапе **намеренно случайный** и меняется от запуска к запуску. Если нужен стабильный вывод — отсортируй ключи:

```go
keys := slices.Sorted(maps.Keys(ages)) // отсортированный слайс ключей
for _, k := range keys {
    fmt.Println(k, ages[k])
}
```

### Какие типы могут быть ключом

Только **сравнимые** (`==`): числа, строки, `bool`, указатели, каналы, массивы, структуры из сравнимых полей, интерфейсы. Слайс, мапа и функция ключом быть не могут.

```go
type Point struct{ X, Y int }
visited := map[Point]bool{}
visited[Point{1, 2}] = true
```

### Множество

Отдельного типа «множество» в Go нет, его делают на мапе с пустой структурой в значении (`struct{}` занимает 0 байт):

```go
seen := map[string]struct{}{}
seen["go"] = struct{}{}
if _, ok := seen["go"]; ok {
    fmt.Println("уже было")
}
```

### Мапа структур

```go
users := map[string]User{"ivan": {Name: "Ivan", Age: 20}}
// users["ivan"].Age++      // ошибка: cannot assign to struct field users["ivan"].Age in map

u := users["ivan"]          // 1) достать копию,
u.Age++                     //    изменить,
users["ivan"] = u           //    положить обратно

ptrs := map[string]*User{"ivan": {Name: "Ivan"}}
ptrs["ivan"].Age++          // 2) или хранить указатели
```

Почему нельзя изменить по месту: при росте мапа переносит значения в новую память, поэтому взять адрес элемента (`&m[k]`) запрещено.

### nil-мапа и вложенные мапы

```go
var m map[string]int  // nil
fmt.Println(m["x"])   // 0 — читать можно
// m["x"] = 1         // panic: assignment to entry in nil map

nested := map[string]map[string]int{}
// nested["a"]["b"] = 1 // panic: внутренняя мапа ещё nil
if nested["a"] == nil {
    nested["a"] = map[string]int{}
}
nested["a"]["b"] = 1
```

### Мапа в функции

Мапа внутри — указатель на хеш-таблицу. Поэтому функция, которая добавляет или удаляет ключи, меняет мапу вызывающего. А вот `m = make(...)` внутри функции заменит только локальную переменную.

### Пакет maps

```go
maps.Keys(m)          // итератор по ключам (раздел 19)
maps.Values(m)        // итератор по значениям
c := maps.Clone(m)    // поверхностная копия
maps.Copy(dst, src)   // скопировать все пары из src в dst
maps.Equal(a, b)
maps.DeleteFunc(m, func(k string, v int) bool { return v == 0 })
clear(m)              // удалить все ключи (встроенная функция)
```

> **Тонкости**
> - **Мапа не потокобезопасна.** Одновременная запись из нескольких горутин (или запись + чтение) — `fatal error: concurrent map writes`. Это не паника, `recover` её не поймает: процесс просто падает. Защищай мьютексом (файл 04).
> - Мапа не уменьшается в памяти после удаления ключей. Огромная мапа, из которой всё удалили, продолжает занимать память — пересоздай её.
> - `cap()` для мапы не существует, только `len()`.
> - Не полагайся на порядок обхода даже в тестах: сравнивай отсортированные данные или через `maps.Equal`.

**Задачи:** «Частота слов», «Мапа структур», «Множества», «Структура как ключ», «Стабильный вывод».

## 15. Строки, байты, руны

### Что такое строка

Строка в Go — **неизменяемая последовательность байт**. Обычно в ней текст в кодировке UTF-8, где один символ занимает от 1 до 4 байт: латиница — 1 байт, кириллица — 2, большинство эмодзи — 4.

```go
s := "Привет, Go!"
fmt.Println(len(s))                    // 17 — БАЙТ, а не символов
fmt.Println(utf8.RuneCountInString(s)) // 11 — символов (рун)
fmt.Println(s[0])                      // 208 — первый БАЙТ буквы «П», а не сама буква
// s[0] = 'п'                          // ошибка: строки неизменяемы
```

- **byte** (`uint8`) — один байт.
- **rune** (`int32`) — один символ Unicode (code point). Литерал руны пишется в одинарных кавычках: `'я'`, `'\n'`.

### Обход строки

```go
for i, r := range "Go, мир" {
    fmt.Printf("%d:%c ", i, r) // 0:G 1:o 2:, 3:  4:м 6:и 8:р
}
```

`range` по строке идёт **по рунам**, а `i` — индекс **байта**, с которого руна начинается. Поэтому индексы прыгают через 2 на кириллице. Обычный цикл `for i := 0; i < len(s); i++` с `s[i]` идёт по **байтам** и разрежет кириллицу пополам.

### Преобразования

```go
b := []byte("hello")  // строка → байты (копия)
b[0] = 'H'
s := string(b)        // байты → строка (копия): "Hello"

r := []rune("привет") // строка → руны: можно работать с символами по индексу
r[0] = 'П'
fmt.Println(string(r)) // Привет

fmt.Println(string(rune(1071))) // "Я" — символ по коду
```

> `string(65)` — **не** `"65"`, а `"A"` (символ с кодом 65). `go vet` об этом предупреждает. Число в строку — только через `strconv.Itoa(65)` или `fmt.Sprint(65)`.

### Литералы

```go
a := "строка с \"кавычками\"\nи переводом строки\t и табом"
b := `сырая строка:
многострочная, \n здесь просто два символа,
удобно для SQL, JSON и регулярных выражений`
```

### Склейка

```go
s := "a" + "b"                       // для пары строк — нормально

var sb strings.Builder               // для склейки в цикле
sb.Grow(1024)                        // необязательно: заранее выделить место
for i := 0; i < 1000; i++ {
    sb.WriteString("x")
    fmt.Fprintf(&sb, "%d,", i)       // Builder — io.Writer, в него можно писать через fmt
}
result := sb.String()

joined := strings.Join([]string{"a", "b", "c"}, ", ") // "a, b, c"
```

`s += "x"` в цикле каждый раз создаёт новую строку и копирует всё накопленное: на тысячах итераций это заметно медленнее.

### Пакет strings — самое нужное

```go
strings.Contains("seafood", "foo")         // true
strings.HasPrefix(s, "http"), strings.HasSuffix(s, ".go")
strings.Index("chicken", "ken")            // 4 (или -1)
strings.Split("a,b,,c", ",")               // ["a" "b" "" "c"] — пустые части остаются
strings.Fields("  a  b   c ")              // ["a" "b" "c"] — по любым пробелам, пустых нет
strings.Join(parts, "-")
strings.Replace(s, "a", "b", -1)           // -1 = заменить все; есть strings.ReplaceAll
strings.ToLower(s), strings.ToUpper(s)     // корректно работают с кириллицей
strings.TrimSpace("  hi \n")               // "hi"
strings.Trim("xxhixx", "x")                // "hi" — второй аргумент: НАБОР символов
strings.TrimPrefix("prefix-body", "prefix-") // "body" — убрать именно эту подстроку
strings.Repeat("ab", 3)                    // "ababab"
strings.EqualFold("Go", "GO")              // true — сравнение без учёта регистра
before, after, found := strings.Cut("key=value", "=") // "key" "value" true
strings.Count("cheese", "e")               // 3
```

Пакет `unicode`: `unicode.IsLetter(r)`, `unicode.IsDigit(r)`, `unicode.IsSpace(r)`, `unicode.ToUpper(r)` — работают с рунами. Пакет `bytes` повторяет функции `strings` для `[]byte`.

> **Тонкости**
> - `strings.TrimLeft(s, "abc")` и `TrimRight` убирают **любые символы из набора**, а не подстроку. `strings.TrimLeft("aabcx", "abc")` → `"x"`. Для подстроки — `TrimPrefix` / `TrimSuffix`.
> - Срез строки `s[a:b]` режет по **байтам**: `"привет"[:3]` даст «п» и половину «р». Для работы с символами переводи в `[]rune`.
> - Сравнение `==` и `<` для строк — побайтовое, лексикографическое. `"Б" < "а"` → `true`, потому что сравниваются коды. Для «человеческой» сортировки с учётом языка нужен пакет `golang.org/x/text/collate`.
> - Конвертации `[]byte(s)` и `string(b)` копируют данные. В горячих местах это заметно, но в обычном коде не думай об этом.

**Задачи:** «Строки и руны», «Шифр Цезаря», «Мини-grep».

## 16. Структуры

Структура — набор именованных полей. Это основной способ описать сущность: пользователь, заказ, конфиг.

```go
type User struct {
    ID        int64
    Name      string
    Email     string
    Tags      []string
    CreatedAt time.Time
}

u1 := User{ID: 1, Name: "Ivan"}  // с именами полей — так и пиши; остальные поля получат нулевые значения
u2 := User{}                     // все поля нулевые
var u3 User                      // то же самое
p := &User{Name: "Anna"}         // указатель на новую структуру

u1.Email = "ivan@example.com"
p.Name = "Anna K."               // через указатель — тот же синтаксис
```

Литерал без имён полей (`User{1, "Ivan", "", nil, time.Time{}}`) требует перечислить все поля по порядку и ломается при добавлении нового поля. Используй только имена.

### Конструкторы

Конструкторов как в других языках нет. По соглашению делают функцию `New...`, которая проверяет входные данные и возвращает готовое значение:

```go
func NewUser(name, email string) (*User, error) {
    if name == "" {
        return nil, errors.New("name is required")
    }
    return &User{Name: name, Email: email, CreatedAt: time.Now()}, nil
}
```

Если в пакете один главный тип, конструктор называют просто `New`: `account.New(...)`.

### Видимость полей

Поля с заглавной буквы видны из других пакетов, со строчной — только в своём. Так делают инкапсуляцию: `balance` нельзя изменить снаружи в обход метода `Deposit`.

```go
type Account struct {
    Owner   string // видно всем
    balance int64  // только внутри пакета
}
```

`encoding/json` тоже видит только экспортируемые поля: неэкспортируемые в JSON не попадут.

### Теги

Строка после типа поля — тег. Её читают библиотеки через рефлексию:

```go
type User struct {
    ID    int64  `json:"id" db:"id"`
    Name  string `json:"name"`
    Email string `json:"email,omitempty"` // не выводить, если пустое
    Pass  string `json:"-"`               // никогда не выводить
}
```

### Анонимные структуры

Структура без объявленного типа — для одноразовых данных:

```go
resp := struct {
    OK    bool `json:"ok"`
    Count int  `json:"count"`
}{OK: true, Count: 3}

tests := []struct {          // так пишут табличные тесты (файл 05)
    in   string
    want int
}{
    {"a", 1},
    {"bb", 2},
}
```

### Сравнение и копирование

- Структуры сравнимы через `==`, если сравнимы **все** поля. Структура со слайсом, мапой или функцией внутри — уже нет.
- Присваивание копирует все поля, но копия **поверхностная**: слайсы и мапы внутри по-прежнему смотрят на общие данные.
  ```go
  a := User{Name: "Ivan", Tags: []string{"admin"}}
  b := a
  b.Name = "Petr"     // a.Name не изменится
  b.Tags[0] = "guest" // a.Tags[0] тоже станет "guest" — слайс общий
  ```

### Пустая структура

`struct{}` занимает 0 байт. Используют как значение в множестве (`map[string]struct{}`) и как сигнал в каналах (`chan struct{}`, файл 04).

> **Тонкости**
> - Нулевое значение структуры — валидное значение. Проектируй типы так, чтобы `var x T` можно было сразу использовать или чтобы его некорректность была очевидна.
> - Порядок полей влияет на размер структуры из-за выравнивания (файл 19). Для обычного кода не важно.

## 17. Методы

Метод — функция с **получателем** (receiver): она «принадлежит» типу.

```go
type Rect struct{ W, H float64 }

func (r Rect) Area() float64 {   // value receiver: работает с копией
    return r.W * r.H
}

func (r *Rect) Scale(k float64) { // pointer receiver: меняет оригинал
    r.W *= k
    r.H *= k
}

r := Rect{W: 2, H: 3}
r.Scale(2)            // Go сам возьмёт &r
fmt.Println(r.Area()) // 24
```

Методы можно объявлять для **любого своего типа** в своём пакете, не только для структур:

```go
type Celsius float64
func (c Celsius) Fahrenheit() float64 { return float64(c)*9/5 + 32 }

type IntList []int
func (l IntList) Sum() int { ... }
```

Нельзя добавить метод встроенному типу (`int`) или типу из другого пакета (`time.Time`) — объяви свой тип на их основе.

### Value или pointer receiver

Бери **pointer receiver**, если:
- метод изменяет получателя;
- структура большая, и копировать её на каждый вызов дорого;
- в структуре есть то, что нельзя копировать (`sync.Mutex`);
- другие методы типа уже с pointer receiver — **держи все методы типа одинаковыми**.

**Value receiver** — для маленьких неизменяемых значений: `time.Time`, `Point`, `Celsius`.

### Автоматические & и *

```go
r := Rect{W: 1, H: 1}
r.Scale(2)   // на самом деле (&r).Scale(2)

p := &Rect{W: 1, H: 1}
p.Area()     // на самом деле (*p).Area()
```

Но автоматически взять адрес можно только у **адресуемого** значения (переменной, элемента слайса, поля адресуемой структуры). Не получится:

```go
Rect{W: 1}.Scale(2)       // ошибка: литерал не адресуем
rects := map[string]Rect{"a": {1, 1}}
rects["a"].Scale(2)       // ошибка: элемент мапы не адресуем
```

### Метод на nil-указателе

Метод с pointer receiver можно вызвать на `nil` — получатель просто будет `nil`. Иногда это используют специально:

```go
type Node struct{ Val int; Next *Node }

func (n *Node) Len() int {
    if n == nil {
        return 0
    }
    return 1 + n.Next.Len()
}
```

Но если метод обращается к полям без проверки — будет panic.

### Значения-методы

Метод можно сохранить в переменную вместе с получателем:

```go
acc := &Account{}
deposit := acc.Deposit // «привязанный» метод: получатель запомнен
deposit(100)           // то же, что acc.Deposit(100)
```

Так метод передают как обычную функцию: в `http.HandleFunc("/", srv.handleIndex)`, в `slices.SortFunc`, в горутину.

### Stringer

Если у типа есть метод `String() string`, пакет `fmt` вызывает его при печати:

```go
func (u User) String() string { return fmt.Sprintf("%s <%s>", u.Name, u.Email) }
fmt.Println(u) // Ivan <ivan@example.com>
```

Это пример интерфейса (`fmt.Stringer`) — подробно в файле 03.

> **Тонкости**
> - Набор методов (method set): у значения типа `T` есть только методы с value receiver, у `*T` — все. Это определяет, реализует ли тип интерфейс (файл 03). Типичная ошибка: методы объявлены на `*T`, а в интерфейс передают `T`.
> - Если тип содержит `sync.Mutex`, его нельзя копировать: используй только pointer receiver и передавай указатель. `go vet` найдёт такие копии.
> - В Go нет `this` и `self`: получатель называют коротко по первой букве типа (`r`, `u`, `acc`) и одинаково во всех методах.

**Задачи:** «Банковский счёт», «Матрицы» (метод `String()`), «Перечисление статусов заказа».

## 18. Встраивание

Наследования в Go нет. Вместо него — **встраивание** (embedding): поле без имени, у которого «поднимаются» наружу поля и методы.

```go
type Person struct {
    Name string
}

func (p Person) Greet() string { return "Hi, " + p.Name }

type Employee struct {
    Person          // встраивание: тип без имени поля
    Position string
}

e := Employee{
    Person:   Person{Name: "Ivan"}, // при создании обращаемся по имени типа
    Position: "developer",
}
fmt.Println(e.Name)        // поле Person «поднялось»: то же, что e.Person.Name
fmt.Println(e.Greet())     // и метод тоже
fmt.Println(e.Person.Name) // явный путь тоже работает
```

### Встраивание — не наследование

`Employee` **не является** `Person`. Функция `func greet(p Person)` не примет `Employee`, нужно явно передать `e.Person`. Подстановка одного типа вместо другого в Go делается через интерфейсы: если у `Employee` есть все методы интерфейса (включая поднятые), он его реализует.

### Перекрытие

Если у внешней структуры есть поле или метод с тем же именем, оно перекрывает встроенное:

```go
func (e Employee) Greet() string {
    return e.Person.Greet() + ", " + e.Position // до встроенного можно добраться явно
}
```

Если два встроенных типа дают одинаковое имя на одном уровне и внешний тип его не перекрывает, обращение к этому имени — ошибка компиляции `ambiguous selector`. Пока к имени не обращаются, ошибки нет.

### Встраивание указателя

```go
type Service struct {
    *Logger // встроен указатель
}
s := Service{}  // Logger == nil
s.Log("x")      // panic, если Log обращается к полям Logger
```

### Где встраивание используют

- Переиспользовать общие поля и методы: базовая модель с `ID`, `CreatedAt`, `UpdatedAt`.
- Обёртки: структура встраивает `http.ResponseWriter` и перекрывает только `WriteHeader`, чтобы запомнить статус ответа (пригодится в middleware, файл 06).
- Встраивание интерфейсов в интерфейсы: `io.ReadWriter` = `io.Reader` + `io.Writer` (файл 03).

> **Тонкости**
> - Встроенный `sync.Mutex` в экспортируемой структуре делает методы `Lock` и `Unlock` частью её публичного API. Обычно лучше именованное неэкспортируемое поле `mu sync.Mutex`.
> - JSON «расплющивает» поля встроенной структуры: поля `Person` окажутся на верхнем уровне объекта `Employee`.

**Задачи:** «Встраивание», «Сравнение и анонимные структуры».

## 19. Итераторы

С Go 1.23 `for … range` умеет ходить не только по слайсам, мапам и каналам, но и по **функциям** определённого вида. Такая функция называется итератором.

```go
// iter.Seq[V]     = func(yield func(V) bool)
// iter.Seq2[K, V] = func(yield func(K, V) bool)

func Countdown(n int) iter.Seq[int] {
    return func(yield func(int) bool) {
        for i := n; i > 0; i-- {
            if !yield(i) { // отдать значение в тело цикла
                return     // false = снаружи сделали break или return
            }
        }
    }
}

for x := range Countdown(3) {
    fmt.Println(x) // 3, 2, 1
}
```

Как это работает: тело цикла `for … range` превращается в функцию `yield`. Итератор сам решает, сколько раз и с какими значениями её вызвать. Когда в теле цикла срабатывает `break` или `return`, `yield` возвращает `false`, и итератор **обязан** прекратить работу.

Зачем это нужно:
- обходить свои коллекции (дерево, связный список) обычным `for range`;
- генерировать последовательности лениво, не создавая слайс целиком (строки огромного файла, бесконечные последовательности);
- склеивать преобразования: «отфильтровать → преобразовать → взять первые 10».

### Итераторы в стандартной библиотеке

```go
m := map[string]int{"b": 2, "a": 1}

for k := range maps.Keys(m) { }              // ключи
for v := range maps.Values(m) { }            // значения
keys := slices.Sorted(maps.Keys(m))          // ["a" "b"] — собрать и отсортировать
vals := slices.Collect(maps.Values(m))       // собрать в слайс

s := []string{"x", "y", "z"}
for i, v := range slices.Backward(s) { }     // с конца
for chunk := range slices.Chunk(s, 2) { }    // ["x" "y"], ["z"]

for line := range strings.Lines(text) { }    // строки текста (с \n на конце)
for part := range strings.SplitSeq(csv, ",") { } // как Split, но без создания слайса
```

> **Тонкости**
> - Если итератор продолжит вызывать `yield` после того, как тот вернул `false`, будет panic: `range function continued iteration after function for loop body returned false`.
> - Итератор — обычная функция: его можно хранить, передавать и вызывать много раз. Каждый `for range` по нему начинает обход заново.
> - Итераторы — новая часть языка. В старом коде вместо них пишут методы вроде `Next()` / `Value()` (как у `bufio.Scanner` и `sql.Rows`) или возвращают слайс.

**Задачи:** «Свои итераторы», «Итераторы стандартной библиотеки».

## 20. Встроенные функции

Их не нужно импортировать — они часть языка.

| Функция | Что делает |
|---|---|
| `len(x)` | длина строки (в байтах), слайса, массива, мапы, канала |
| `cap(x)` | ёмкость слайса, массива, канала |
| `append(s, ...)` | добавить элементы в слайс |
| `copy(dst, src)` | скопировать элементы слайса, вернуть их число |
| `delete(m, k)` | удалить ключ из мапы |
| `clear(x)` | мапа: удалить все ключи; слайс: обнулить все элементы (len не меняется) |
| `make(T, ...)` | создать слайс, мапу или канал, готовые к работе |
| `new(T)` | выделить память под нулевое значение `T` и вернуть `*T` |
| `min(a, b, ...)`, `max(...)` | минимум и максимум (числа, строки) |
| `panic(v)`, `recover()` | раздел 10 |
| `close(ch)` | закрыть канал (файл 04) |
| `print`, `println` | отладочный вывод в stderr — в коде не используй, бери `fmt` или `log` |

### make и new

- `make` — только для слайсов, мап и каналов: они требуют внутренней инициализации, и `make` возвращает **само значение**, готовое к работе.
- `new(T)` — для любого типа: возвращает **указатель** на нулевое значение. На практике вместо `new(User)` пишут `&User{}`.

```go
m := make(map[string]int) // готовая мапа
p := new(map[string]int)  // указатель на nil-мапу — почти никогда не нужно
```

## 21. Стандартная библиотека: что нужно с первого дня

Стандартная библиотека Go большая и качественная. Для бэкенда многое (HTTP-сервер, JSON, работа с БД, криптография) есть без внешних зависимостей. Ниже — пакеты, которые понадобятся уже в задачах этого файла.

### fmt — вывод и форматирование

```go
fmt.Println("a", 1, true)           // через пробел + перевод строки
fmt.Print("без перевода строки")
fmt.Printf("%s is %d\n", name, age) // по шаблону, перевод строки сам не ставится
s := fmt.Sprintf("id=%d", id)       // в строку
err := fmt.Errorf("load %s: %w", path, err) // ошибка (раздел 9)
fmt.Fprintln(os.Stderr, "ошибка!")  // в любой io.Writer: файл, буфер, HTTP-ответ
```

| Глагол | Что выводит | Пример |
|---|---|---|
| `%v` | значение в формате по умолчанию | `{1 Ivan}` |
| `%+v` | структура с именами полей | `{ID:1 Name:Ivan}` |
| `%#v` | как Go-код | `main.User{ID:1, Name:"Ivan"}` |
| `%T` | тип | `main.User` |
| `%d` | целое | `42` |
| `%5d`, `%-5d`, `%05d` | ширина, выравнивание влево, нули | `   42`, `42   `, `00042` |
| `%s`, `%q` | строка, строка в кавычках | `hi`, `"hi"` |
| `%f`, `%.2f`, `%8.2f` | дробное, 2 знака, ширина 8 | `3.141593`, `3.14`, `    3.14` |
| `%t` | bool | `true` |
| `%x`, `%X` | шестнадцатеричное | `ff` |
| `%b` | двоичное | `101` |
| `%c`, `%U` | символ руны, код Unicode | `я`, `U+044F` |
| `%p` | адрес указателя | `0xc000012345` |
| `%%` | знак процента | `%` |

`go vet` проверяет, что глаголы соответствуют типам аргументов, — запускай его.

### strconv — строки ⇄ числа

```go
n, err := strconv.Atoi("42")                // string → int
s := strconv.Itoa(42)                       // int → string
i64, err := strconv.ParseInt("ff", 16, 64)  // с основанием и размером: 255
f, err := strconv.ParseFloat("3.14", 64)
b, err := strconv.ParseBool("true")         // принимает 1, t, T, TRUE, true, True и т. п.
fs := strconv.FormatFloat(3.14159, 'f', 2, 64) // "3.14"
q := strconv.Quote("hi\n")                  // "\"hi\\n\""

_, err = strconv.Atoi("abc")
fmt.Println(err) // strconv.Atoi: parsing "abc": invalid syntax
```

### time — время и длительности

```go
now := time.Now()
start := time.Now()
// ... работа ...
elapsed := time.Since(start)            // time.Duration
fmt.Println(elapsed)                    // 1.234567ms

d := 90 * time.Second                   // Duration — это int64 наносекунд
fmt.Println(d)                          // 1m30s
d2, err := time.ParseDuration("1h15m")
tomorrow := now.Add(24 * time.Hour)
diff := tomorrow.Sub(now)               // 24h0m0s
time.Sleep(500 * time.Millisecond)
```

**Форматирование** задаётся не буквами `YYYY-MM-DD`, а **эталонной датой** `Mon Jan 2 15:04:05 MST 2006` (запомнить: 1 2 3 4 5 6 7 — месяц, день, час, минута, секунда, год, пояс −7):

```go
now.Format("2006-01-02 15:04:05")   // 2026-11-03 19:34:00
now.Format("02.01.2006")            // 03.11.2026
now.Format(time.RFC3339)            // 2026-11-03T19:34:00+03:00 — стандарт для API
t, err := time.Parse("2006-01-02", "2004-05-17")
t2, err := time.ParseInLocation("2006-01-02 15:04", "2026-12-31 18:00", time.Local)

minsk, err := time.LoadLocation("Europe/Minsk")
fmt.Println(now.In(minsk).Format("15:04"))
```

Есть готовые константы: `time.DateTime` (`2006-01-02 15:04:05`), `time.DateOnly`, `time.TimeOnly`, `time.RFC3339`.

> **Тонкости time**
> - Сравнивай время методами `t.Equal(u)`, `t.Before(u)`, `t.After(u)`, а не `==`: `==` сравнивает ещё и часовой пояс и служебные поля.
> - `time.Parse` без пояса в строке считает время в **UTC**. Для местного времени — `ParseInLocation`.
> - В БД и API храни время в UTC (`t.UTC()`), а в местное переводи только при показе пользователю.
> - `time.Sleep(5)` — это 5 **наносекунд**. Всегда умножай на единицу: `5 * time.Second`.

### os — файлы, аргументы, окружение

```go
args := os.Args[1:]                 // аргументы командной строки (os.Args[0] — имя программы)
port := os.Getenv("PORT")           // "" если переменной нет
port, ok := os.LookupEnv("PORT")    // отличить «нет» от «пустая строка»

data, err := os.ReadFile("in.txt")  // прочитать файл целиком ([]byte)
err = os.WriteFile("out.txt", data, 0o644) // записать целиком, 0o644 — права rw-r--r--
if errors.Is(err, os.ErrNotExist) { /* файла нет */ }

f, err := os.Open("in.txt")         // открыть на чтение (вернёт *os.File — это io.Reader)
f, err = os.Create("out.txt")       // создать или обрезать на запись
defer f.Close()

os.MkdirAll("data/logs", 0o755)
os.Exit(1)                          // выйти с кодом 1 (defer не выполнятся!)
```

### bufio — построчное чтение

```go
scanner := bufio.NewScanner(os.Stdin) // или файл: bufio.NewScanner(f)
for scanner.Scan() {
    line := scanner.Text()            // строка без \n
    fmt.Println(">", line)
}
if err := scanner.Err(); err != nil { // ошибку проверяют ПОСЛЕ цикла
    log.Fatal(err)
}

scanner.Split(bufio.ScanWords)        // читать по словам вместо строк

w := bufio.NewWriter(os.Stdout)       // буферизованная запись — быстро для большого вывода
defer w.Flush()                       // без Flush данные останутся в буфере
fmt.Fprintln(w, "строка")
```

> По умолчанию `Scanner` не читает строки длиннее 64 КБ: `Scan()` вернёт `false`, а `Err()` — `token too long`. Для длинных строк увеличь буфер: `scanner.Buffer(make([]byte, 1024*1024), 1024*1024)`.

### flag — флаги командной строки

```go
func main() {
    n := flag.Int("n", 10, "сколько строк показать")
    verbose := flag.Bool("v", false, "подробный вывод")
    flag.Parse()

    files := flag.Args() // всё, что осталось после флагов
    fmt.Println(*n, *verbose, files)
}
// go run . -n 5 -v a.txt b.txt
// go run . -h — справка генерируется автоматически
```

Флаги должны идти **до** позиционных аргументов: в `go run . a.txt -n 5` флаг `-n` будет считаться именем файла.

### encoding/json

```go
type Task struct {
    ID    int64     `json:"id"`
    Title string    `json:"title"`
    Done  bool      `json:"done"`
    Tags  []string  `json:"tags,omitempty"`
    DueAt time.Time `json:"due_at,omitzero"` // Go 1.24+: пропустить нулевое время
}

t := Task{ID: 1, Title: "Купить молоко"}
b, err := json.Marshal(t)                  // {"id":1,"title":"Купить молоко","done":false}
b, err = json.MarshalIndent(t, "", "  ")   // с отступами

var got Task
err = json.Unmarshal(b, &got)              // ОБЯЗАТЕЛЬНО указатель

var tasks []Task
err = json.Unmarshal([]byte(`[{"id":1},{"id":2}]`), &tasks)

dec := json.NewDecoder(r)                  // читать из потока (файл, тело HTTP-запроса)
dec.DisallowUnknownFields()                // ошибка на неизвестные поля
err = dec.Decode(&got)
```

> **Тонкости JSON**
> - В JSON попадают только **экспортируемые** поля (с заглавной буквы). Частая ошибка: структура с полями `id`, `title` маршалится в `{}`.
> - Лишние поля во входном JSON по умолчанию молча игнорируются, отсутствующие — получают нулевые значения.
> - Число, распакованное в `any` или `map[string]any`, становится `float64`. Большие id могут потерять точность — распаковывай в структуру с `int64`.
> - `omitempty` не работает для структур (`time.Time{}` всё равно выведется) — для них есть `omitzero`.

## 23. Шпаргалка ловушек

Перечитай перед собеседованием. Каждый пункт разобран в разделе, номер которого в скобках.

**Синтаксис и переменные**
1. Неиспользуемая переменная или импорт — ошибка компиляции (0).
2. `{` обязана стоять на той же строке, что и `if` / `for` / `func` (0).
3. `:=` во вложенном блоке затеняет внешнюю переменную — так теряют `err` (2).
4. Нет неявных преобразований: `int32 + int64` не скомпилируется (3).
5. `x++` — инструкция, а не выражение. Тернарного оператора нет (5).

**Числа**
6. Целочисленное деление: `7/2 == 3`, `-7/2 == -3`. И `1 / 3` для констант = 0 (3, 4).
7. Переполнение во время выполнения молчаливое: `int8(127) + 1 == -128` (3).
8. `0.1 + 0.2 != 0.3` для float-переменных. Деньги — в целых копейках (3).
9. `string(65) == "A"`, а не `"65"` (15).

**Управление потоком**
10. `break` в `switch` или `select` внутри `for` выходит только из `switch` (6).
11. `for _, v := range s` — `v` копия, изменения не попадут в слайс (6, 13).
12. С Go 1.22 у каждой итерации своя переменная цикла, поведение зависит от `go` в `go.mod` (6).

**Функции, defer, panic**
13. Аргументы `defer` вычисляются сразу, выполнение — в конце функции, порядок LIFO (8).
14. `defer` в цикле копит ресурсы до конца функции (8).
15. `os.Exit` и `log.Fatal` не выполняют `defer` (8).
16. `recover` работает только в `defer` и только в своей горутине (10).

**Слайсы**
17. Подслайс и исходный слайс делят один массив (13).
18. `append` может вернуть слайс на тот же массив или на новый — всегда присваивай результат (13).
19. `append` внутри функции не виден вызывающему, если результат не вернуть (13).
20. nil-слайс и пустой: одинаковы почти везде, но в JSON `null` против `[]` (13).
21. Маленький подслайс держит в памяти весь большой массив (13).

**Мапы**
22. Запись в nil-мапу — panic, чтение — безопасно (14).
23. Порядок обхода случайный (14).
24. `m[k].Field = x` не компилируется для мапы структур (14).
25. Одновременная запись из горутин — fatal error, который не ловится `recover` (14).

**Строки**
26. `len(s)` — байты, а не символы. `s[i]` — байт (15).
27. `TrimLeft` / `TrimRight` убирают набор символов, а не подстроку (15).
28. Склейка `+=` в цикле медленная — `strings.Builder` (15).

**Структуры и методы**
29. Копия структуры поверхностная: слайсы и мапы внутри общие (16).
30. В JSON попадают только экспортируемые поля (16, 21).
31. Метод с pointer receiver нельзя вызвать на элементе мапы или литерале (17).
32. Методы на `*T` не входят в набор методов `T` — важно для интерфейсов (17, файл 03).
33. Встраивание — не наследование: `Employee` не передать туда, где ждут `Person` (18).

**Время**
34. Формат даты — эталонная дата `2006-01-02 15:04:05` (21).
35. `time.Sleep(5)` — 5 наносекунд (21).

### Функции, замыкания, defer
- [ ] ⭐⭐ **Функции как значения.**

  ```go
  func double() (result int) {
      defer func() { result *= 2 }()
      return 3
  }

  func main() {
      for i := 0; i < 3; i++ {
          defer fmt.Print(i, " ")
      }
      x := 1
      defer fmt.Println("defer x =", x)

  ```

  ```

  defer x = 1
  2 1 0
  ```

  Затем напиши `SafeGo(f func())`, которая запускает горутину с recover внутри и логирует панику вместо падения программы.
  <details><summary>Ответ</summary>

  Программа упадёт, `err:` не напечатается. `recover` в `SafeCall` работает только для паники в **той же** горутине, а паника случилась в новой, где своего recover нет. Необработанная паника в любой горутине завершает весь процесс. Поэтому recover ставят внутрь каждой горутины, которую запускаешь (что и делает `SafeGo`).
  </details>

### Слайсы и массивы
- [ ] ⭐⭐ **Предскажи вывод: слайсы в функциях.**
  ```go
  func addOne(s []int)   { s = append(s, 1) }
  func setFirst(s []int) { s[0] = 100 }

  func main() {
      a := []int{1, 2, 3}
      addOne(a)
      setFirst(a)
      fmt.Println(a)

      b := make([]int, 3, 10)
      addOne(b)
      fmt.Println(b, len(b), b[:4])

      var n []int
      e := []int{}
      fmt.Println(n == nil, e == nil, len(n), len(e))
      j1, _ := json.Marshal(n)
      j2, _ := json.Marshal(e)
      fmt.Println(string(j1), string(j2))

      src := []int{1, 2, 3, 4, 5}
      part := src[1:3]
      part = append(part, 99)
      fmt.Println(src, part, cap(part))

      safe := src[1:3:3]
      safe = append(safe, 7)
      fmt.Println(src, safe)
  }
  ```
  <details><summary>Ответ</summary>

  - `[100 2 3]` — `append` внутри `addOne` изменил только локальную копию заголовка (cap не хватило, создан новый массив), а `s[0] = 100` записал в общий массив.
  - `[0 0 0] 3 [0 0 0 1]` — места хватило, и `append` записал 1 в общий массив за пределами `len` вызывающего. Через `b[:4]` его видно.
  - `true false 0 0` и `null []` — nil-слайс и пустой отличаются только сравнением с nil и в JSON.
  - `[1 2 3 99 5] [2 3 99] 4` — у `part` cap = 4 (до конца `src`), поэтому `append` перезаписал `src[3]`.
  - `[1 2 3 99 5] [2 3 7]` — трёхиндексный срез ограничил cap до 2, и `append` создал новый массив, не тронув `src`.
  </details>
- [ ] ⭐⭐ **Утилиты для слайсов.** Сначала вручную, потом найди аналоги в пакете `slices` и сравни:
  - `RemoveOrdered(s []int, i int) []int` (через `append(s[:i], s[i+1:]...)`) и `RemoveFast` (поменять с последним и укоротить, порядок не важен). Выведи исходный слайс после удаления и объясни, почему он изменился.
  - `Insert(s []int, i int, v int) []int`.
  - `FilterInPlace(s []int, keep func(int) bool) []int` без нового выделения памяти (приём `res := s[:0]`).
  - `Dedup(sorted []int) []int` — убрать подряд идущие дубли.
  - `Chunk(s []int, n int) [][]int` — разбить на части по n.
  - Аналоги: `slices.Delete`, `slices.Insert`, `slices.DeleteFunc`, `slices.Compact`, `slices.Chunk`.
- [ ] ⭐ **Массив — это значение.** Предскажи вывод:
  ```go
  arr := [3]int{1, 2, 3}
  arr2 := arr
  arr2[0] = 100
  sl := arr[:]
  sl[1] = 200
  fmt.Println(arr, arr2, arr == [3]int{1, 200, 3})
  ```
  Затем напиши две функции: `func zeroValue(a [3]int)` и `func zeroPtr(a *[3]int)`, которые обнуляют массив, и проверь, какая из них меняет оригинал.
  <details><summary>Ответ</summary>

  `[1 200 3] [100 2 3] true`. `arr2 := arr` копирует весь массив, поэтому `arr2` независим. `arr[:]` — слайс, смотрящий на `arr`, поэтому изменение через `sl` видно в `arr`. Массивы сравнимы через `==`.
  </details>

### Стандартная библиотека
- [ ] ⭐ **Глаголы fmt.** Для `User{ID: 1, Name: "Ivan", Tags: []string{"admin"}}` выведи результат `%v`, `%+v`, `%#v`, `%T`, а для имени — `%q`. Напечатай таблицу пользователей с выравниванием: имя слева в 10 символов, баланс справа с двумя знаками после запятой (`%-10s|%10.2f`).
